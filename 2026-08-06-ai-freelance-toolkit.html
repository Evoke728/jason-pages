先練這個

挑一個你自己每週都要做的事，例如整理產業新聞。拆成三個 agent：搜集、篩選、寫成摘要。跑通之後你會理解 agent 分工的邏輯，也會發現哪些環節其實不需要 agent。

⚠️ 多 agent 流程的失敗模式很隱蔽。它不會報錯，它會產出一份看起來很完整但內容錯誤的東西。所以每一條你交付給客戶的流程，都要有人工審核的節點。

不要把 agent 數量當成賣點。能用兩個 agent 解決的事，用五個只會讓成本變高、除錯變難。

先練這個

四個步驟
把工具變成收入

步驟一 · 先跑通一個真實案例

選一個工具，用在你自己身上，跑到真的可用為止。記錄三件事：花了多少時間、遇到哪些坑、省下多少工時。

這三個數字之後全部用得到：時間變成你的報價基礎，坑變成你的專業說詞，省下的工時變成客戶的購買理由。
步驟二 · 把它寫成一個服務

服務跟工具的差別在於，服務有明確的交付清單、時程與售後範圍。

服務設計 Prompt
你是我的接案顧問。
我要把一個 AI 工具包裝成可以販售的服務。

工具：
【工具名稱與它能做的事】

我已經完成的實測：
【描述你自己跑通的案例、花了多久、省下多少時間】

目標客戶：
【產業、公司規模、你認為他們的痛點】

任務：
幫我設計這個服務的完整方案，包含以下段落。

1. 服務名稱（三個版本，一個功能導向、一個結果導向、一個痛點導向）
2. 一句話說明（讓非技術背景的老闆三秒內聽懂）
3. 交付清單（列出五到八項具體可驗收的產出）
4. 時程規劃（從簽約到交付的階段與天數）
5. 售後範圍（包含什麼、不包含什麼，各列三項）
6. 三個定價方案（基礎、標準、進階，說明差異在哪）
7. 客戶最可能提出的五個疑慮，以及對應的回答

規則：
不要使用「賦能」「數位轉型」這類抽象詞
每一項交付內容都要具體到客戶能判斷有沒有做到
步驟三 · 找到第一個客戶

第一個客戶通常來自你已經認識的人。列出你認識的、有公司的人，逐一想「他公司裡有沒有人在做重複的事」。

開口的方式
不要賣工具，講結果。「我做了一個東西，可以幫你把每天早上那件事變成自動的，要不要看一下」比「我學會了 AI 自動化」有效得多。
第一個案子可以做得便宜，甚至免費，換取一份可以公開的案例與見證。案例是你接第二個案子的槓桿。
步驟四 · 報價與簽約
報價 Prompt
你是我的報價助手。

案子背景：
【客戶產業、公司規模、他們現在怎麼做這件事】

我要交付的內容：
【貼上你的交付清單】

我預估的工作時間：
【建置幾小時、後續維護每月幾小時】

客戶目前的成本：
【現在做這件事花多少人力、多少時間、多少錢】

任務：
1. 計算這個案子的成本結構，包含我的工時、API 費用、第三方服務費用
2. 提出三個定價方案與各自的報價
3. 寫一段報價說明，重點放在客戶省下的成本，不要只講技術
4. 列出報價單應該包含的所有條款，特別是：
   - 修改次數的上限
   - 維護範圍與不包含的項目
   - 網站改版或平台 API 變動時的處理方式
   - 付款節點
5. 列出這個案子最可能出問題的三個地方，以及合約裡該怎麼寫

輸出成一份可以直接寄給客戶的報價單草稿。
五個常見的坑

這五個
先避開

一、工具裝了七個，一個都沒跑通。
七個工具不需要全部學。挑一個，做到能收錢，再學第二個。
二、把 API 成本當成零。
模型、語音、資料抓取都是按用量計費。接案前先估算月成本，並在合約裡設定用量上限。
三、交付一次就結束。
網站會改版、API 會變、平台會調整規則。你的服務要包含維護，這是穩定收入的來源，也是保護你自己的方式。
四、用技術詞跟客戶溝通。
老闆不在意你用了幾個 agent。他在意的是每個月省下多少人力成本、少漏接多少通電話。把技術翻譯成他的語言。
五、跳過人工審核。
AI 產出的東西要有人看過再交付。這一步省不得，它是你的專業保險。
