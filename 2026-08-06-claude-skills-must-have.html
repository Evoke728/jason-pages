Part 0 · 先搞懂三個名詞

大部分人裝到一半卡住
是因為把這三個搞混

名詞是什麼放在哪怎麼裝
Skill一個資料夾，裡面有一個 SKILL.md，教 Claude 怎麼做某一類任務claude.ai 的 Skills 頁面，或 ~/.claude/skills/上傳 ZIP，或把資料夾丟進去
Plugin一個包裹，裡面可以裝好幾個 Skill，加上指令、agent、hook、MCP 設定Claude Code/plugin marketplace add 再 /plugin install
MCP一個會跑起來的服務，讓 Claude 連到外部工具或資料Claude Code 或桌面版claude mcp add，或在設定裡連接
Skill 的運作方式（這決定了你該裝幾個）

Claude 平常只讀每個 Skill 的一行 description，大約一百個 token。只有當你的任務對上那行描述，它才會把完整的 SKILL.md 讀進來。

所以問題不在數量，在相似度
裝十個 Skill 的固定成本很低。問題出在 description 寫得像的 Skill 一多，Claude 判斷「這個任務該用哪一個」的準確度會下降。裝三個功能重疊的寫作 Skill，比裝一個好用的還糟。
這就是為什麼這份清單只有 15 個，而且每個場景不重複。
Part 1 · 三種環境

先確認
你在哪一個

A · claude.ai 網頁版 / 桌面 App

適合：不寫程式的人、內容創作者、要做報告文件的人。

⚠️ 前置設定（沒開這個，Skills 選單會是灰的）：點左下角頭像 → Settings → 進 Capabilities，把 Code execution and file creation 打開 → 回到 Customize → Skills。

官方說明：Skills 在 Free、Pro、Max、Team、Enterprise 方案都能用，關鍵是 code execution 要開著。很多人以為自己方案不夠，其實是這個開關沒打開。
上傳自訂 Skill：在 Skills 頁面點 +，選 ZIP 檔上傳。ZIP 裡面要有一個資料夾，資料夾裡要有 SKILL.md。上傳完會顯示一段摘要，那段摘要是 Claude 告訴你它讀懂了什麼——如果摘要看起來很含糊，代表這個 Skill 的 description 寫得爛，之後觸發會很不穩定。另外，上傳完不等於啟用，還要把旁邊的開關切開。
B · Claude Code（終端機）
方式一 · Plugin marketplace（推薦）
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills
/plugin install example-skills@anthropic-agent-skills
方式二 · 直接放資料夾
個人用（所有專案都吃得到）
~/.claude/skills/<skill-name>/SKILL.md

專案用（跟著 git repo 走，團隊共用）
.claude/skills/<skill-name>/SKILL.md
方式三 · 用 skills CLI
npx -y skills add <github-user>/<repo> --skill <skill-name> --agent claude-code
裝完之後：重開 Claude Code。用 /plugin 檢查有沒有裝進去，用 /mcp 檢查 MCP 有沒有連上。
C · Claude API

透過 /v1/skills 端點上傳，Skill 會綁在整個 workspace，所有成員都能用。這部分屬於開發者範圍，本清單不展開。

10Chrome DevTools MCPMCP server

做什麼：讓 Claude 真的打開瀏覽器，看自己寫出來的畫面、讀 console 錯誤、抓網路請求、跑效能追蹤，然後自己回頭修。

安裝與驗證
claude mcp add chrome-devtools npx chrome-devtools-mcp@latest

claude mcp list
實際 Prompt
我的 dev server 跑在 http://localhost:3000。
用 chrome devtools 打開它，做這幾件事：
1. 截圖首頁
2. 讀 console，把所有 error 跟 warning 列出來
3. 錄一段效能追蹤，告訴我 LCP 是多少、卡在哪個資源
4. 針對前三個問題各給一個具體修法，不要動到其他檔案
⚠️ 這是最多人卡住的地方：預設它會另外開一個全新的 Chrome，沒有你的登入狀態，所以不能叫它去看需要登入的頁面。從 Chrome 136 開始，遠端偵錯在預設設定檔上被擋掉了，要另外開一個 debug 專用的設定檔。

另外提醒：這個 MCP 會把瀏覽器裡的內容暴露給 Claude。不要在有敏感資料的瀏覽器工作階段上用它。
debug 專用設定檔的接法
claude mcp add chrome-devtools -- npx -y chrome-devtools-mcp@latest --browserUrl=http://127.0.0.1:9222
然後另外啟動 Chrome（Windows）
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="%TEMP%\chrome-debug"
Mac 版路徑改成 /Applications/Google Chrome.app/Contents/MacOS/Google Chrome。

Part 4 · 為什麼裝越多反而變差

這決定了
你之後怎麼管理

Claude 怎麼決定要用哪個 Skill：它讀所有已啟用 Skill 的 description，然後判斷哪一個跟你當下的任務最匹配。

問題出在哪：你裝了三個寫作 Skill，description 分別寫著「幫助改善寫作品質」「用於內容創作」「優化文字表達」。這三句話對 Claude 來說幾乎沒有區別，它會挑一個，但你沒辦法預測是哪一個，而且下次可能挑不同的。

三個具體對策
每個場景只留一個。寫作留一個、簡報留一個、程式留一個。功能重疊的直接砍掉，不要留著「以後可能會用到」
自己做的 Skill，description 寫觸發條件，不要寫功能
Claude Code 專用：在 frontmatter 加 disable-model-invocation，Skill 就只能你手動叫，專門用來擋那些會亂跳出來的
✕ 寫得爛description: A skill for writing high-quality social media content.
✓ 寫得好description: Use when the user asks to write Instagram carousel copy, Threads posts, or IG captions in Traditional Chinese. Triggers on phrases like 輪播文案, IG 貼文, Threads 文案. Do NOT use for long-form blog posts or email newsletters.
差別在於：後者寫了「什麼時候用」跟「什麼時候不要用」。Claude 判斷的準確度完全靠這一行。
擋掉自動觸發
disable-model-invocation: true
Part 5 · 裝第三方之前

Skill 不只是文字
它可以包含會執行的程式碼

⚠️ 安裝一個來路不明的 Skill，等於在你的環境裡跑別人的程式。安全研究團隊已經在公開的 Skill marketplace 裡發現過含後門和惡意 hook 的套件。這個生態系目前沒有內建的審核機制，所有把關都要你自己來。
打開 SKILL.md 讀一遍。讀不懂就不要裝
看有沒有 scripts/ 或 hooks/ 資料夾。有的話，裡面的檔案要一行一行看。hook 會在你每次送訊息時自動執行
看 .mcp.json。如果它要起一個 MCP server，確認那個 server 連去哪裡
看 repo 的活躍度。最後一次 commit 是什麼時候、有沒有人開 issue、作者是誰
權限最小化。能裝在單一專案（.claude/skills/）就不要裝在全域（~/.claude/skills/）
不想每個都自己審的話，可以只從有審核流程的 marketplace 裝，例如 Trail of Bits 維護的 trailofbits/skills-curated，他們的說明是每個 PR 都會逐行審過 hook 跟 script。
Part 6 · 常見問題排錯

裝不起來
看這裡

Skills 選單是灰的，或根本找不到
不是方案問題。去 Settings → Capabilities 把「Code execution and file creation」打開。Team 跟 Enterprise 方案的話，要由 owner 在 Organization settings → Skills 開啟。
上傳了 ZIP，但 Claude 都不用它
三個可能。① 上傳完沒有把開關切開，上傳不等於啟用。② ZIP 結構錯了，正確結構是 ZIP 裡有一個資料夾，資料夾裡有 SKILL.md，而不是 SKILL.md 直接放在 ZIP 根目錄。③ description 寫得太模糊。
Claude Code 裝了 plugin 但沒反應
先跑 /plugin 看有沒有在列表裡。有的話重開 Claude Code。還是不行就跑 /reload-plugins。
MCP 顯示連線失敗
跑 claude mcp list 看狀態。用 npx 安裝的先確認 Node.js 版本夠新，直接在終端機跑一次 npx chrome-devtools-mcp@latest --help 看會不會出錯。遠端 MCP 的話檢查是不是要 API key。
frontmatter 報錯 Unexpected key(s)
Agent Skills 規格只允許六個欄位：allowed-tools、compatibility、description、license、metadata、name。多寫別的就會直接失敗。
兩個 Skill 一直互搶
改 description，把「什麼情況不要用」明確寫進去。或者其中一個加 disable-model-invocation: true，改成手動叫。
官方的文件 Skill 在 Claude Code 裡找不到
正常的。docx、pptx、xlsx、pdf 這四個不在 Claude Code 提供，要在 claude.ai 或桌面版用。
