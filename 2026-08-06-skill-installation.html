開始之前

三個
必須先搞懂的觀念

觀念一 · Skill 跟 Plugin 是兩種東西

這兩個詞常常被混用，但安裝方式完全不同。Skill 是單一能力，核心就是一個 SKILL.md 檔案，裡面寫著「什麼情況下該用、要怎麼做」，Claude 在任務符合的時候自己載入，你不用下指令叫它。Plugin 是一個包，裡面可能同時裝了好幾個 Skill、指令、hook、MCP 連接器，安裝走 /plugin 或專屬的 CLI。

名稱實際型態安裝方式
Stop SlopSkill放進 skills 資料夾
Claude MemPluginnpx claude-mem install
UI/UX Pro MaxPlugin（內含 Skill）/plugin marketplace add
Task ObserverSkill放進 skills 資料夾
Find SkillsSkill（搭配 CLI）npx skills
搞錯型態就會裝錯位置，裝錯位置就不會生效。
觀念二 · 兩種安裝位置，差別很大
兩種層級
~/.claude/skills/          ← 使用者層級：所有專案都吃得到
[你的專案]/.claude/skills/  ← 專案層級：只在這個專案生效
這個 Skill 你每個專案都想用 → 放使用者層級（~/.claude/skills/）
這個 Skill 只服務特定專案的規則 → 放專案層級
以這 5 個來說，Stop Slop、Task Observer、Find Skills 都放使用者層級。像「這個客戶的品牌語氣規範」這種，才放專案層級。
觀念三 · Skill 是「建議」，不是「強制」

Claude 讀到 Skill 之後會參考它，但不保證每次都百分之百照做。想提高觸發率，做兩件事：

把 description 寫具體。裡面要出現使用者實際會講的字眼，不要寫抽象的功能描述。
在 CLAUDE.md 加一行明確指示。這比只靠 description 自動比對可靠很多。

01Stop Slop · 清掉 AI 味
解決什麼：AI 寫出來的東西有固定指紋：破折號、「在這個快速變遷的時代」、「讓我們一起探討」、把 is 換成 serves as 這種繞路寫法、還有「不是 A，而是 B」的對比句型。這個 Skill 內建了要砍掉的清單，會在 Claude 產出文字時直接套用。
安裝
進到使用者層級 skills 資料夾並 clone
# 1. 進到使用者層級的 skills 資料夾（沒有就建一個）
mkdir -p ~/.claude/skills
cd ~/.claude/skills
# 2. clone 下來
git clone https://github.com/hardikpandya/stop-slop.git
裝完之後資料夾長這樣
~/.claude/skills/stop-slop/
├── SKILL.md              ← 核心規則
├── references/
│   ├── phrases.md        ← 禁用詞句清單
│   ├── structures.md     ← 禁用結構清單
│   └── examples.md       ← 改寫前後對照
├── README.md
└── LICENSE
確認裝成功

開一個新的 Claude Code session，輸入：

測試指令
幫我寫一段 100 字的產品介紹，主題是一款咖啡訂閱服務。

看輸出裡有沒有破折號、有沒有「在這個…的時代」這類開場。沒有就是生效了。如果沒生效，直接下指令強制觸發：

強制觸發
用 stop-slop 的規則重寫上面這段。
進階用法：加入你自己的禁用清單

references/phrases.md 是純文字檔，你可以直接編輯，把自己討厭的句型加進去。

額外禁用（中文）
## 額外禁用（中文）
- 「真正的 X，是……」
- 「不只是……更是……」
- 「這讓我想到……」
- 「值得注意的是……」
- 「你是否曾經……」
- 「現在就開始……」
- 所有全形破折號 ——
加完存檔就生效，不用重裝。
⚠️ 它處理的是語言表層，不會幫你把空洞的內容變得有料。文字沒有具體資訊的時候，去掉 AI 味只會變成沒有 AI 味的廢話。內容的密度還是你自己要給。
02Claude Mem · 跨對話的記憶
解決什麼：每開一個新對話，Claude 就從零開始。你要重講一次專案背景、重講一次語氣要求、重講一次上次改到哪裡。Claude Mem 在 session 進行中把工具操作記錄下來，壓縮成語意摘要，下次開新 session 的時候自動注入。
⚠️ 這是 plugin，不是 skill。用 npm 全域安裝只會裝到 SDK，不會註冊 hook。
安裝
安裝
npx claude-mem install
裝完必須重啟 Claude Code，hook 才會掛上。
確認裝成功

它會起一個本機的 web viewer，開瀏覽器看 http://localhost:37777。隨便在 Claude Code 裡跑一個任務（讀個檔案、寫段程式都可以），回去重整這個頁面。有看到新的 observation 跑出來，就是接上了。

看不到的話，依序檢查：① 有沒有重啟 Claude Code ② hook 有沒有掛上（/hooks 看一下）③ 背景 worker 有沒有在跑

運作機制（知道了比較好調）
時機做的事
SessionStart把過往的壓縮索引注入到 context
UserPromptSubmit記錄你的 prompt
PostToolUse每次工具呼叫後抓一筆 observation
Stop產生階段摘要
SessionEnd產生完整 session 摘要
資料全部存在本機的 SQLite，搜尋用 FTS5 全文檢索加上向量索引。沒有雲端，沒有外部 API。
實際場景

IG 內容專案開了半年，累積品牌語氣規則、禁用句型、受眾輪廓、過去哪幾篇數據好、哪幾種鉤子失敗過。現在開新對話直接說：

實際使用範例
接續 IG 輪播專案，這次主題是 Claude Skills，先給我 5 個鉤子方向。

它知道要什麼語氣、知道哪些句型不能用、知道受眾是誰。

⚠️ 注入的記憶會吃 token。每一個 token 的記憶都在跟當下任務的推理空間競爭。剛裝的前兩週留意一下用量，太肥就去調注入的深度。記憶存在你這台機器上，換電腦不會跟著走，要自己同步那個 SQLite 檔——這是隱私上的優點，也是可攜性上的限制。
03UI/UX Pro Max · 介面不像 AI 做的
解決什麼：叫 AI 做網頁，出來的東西十次有九次長一樣——一樣的 Tailwind 預設色、一樣的圓角卡片、一樣的置中 hero 區塊，因為模型的訓練資料裡這種畫面最多。這個 plugin 內建了 UI 風格庫、配色系統、字體配對、圖表型別、UX 規則，讓 Claude 從資料庫裡挑，而不是自己即興。
安裝
方式一 · Claude Code plugin（推薦）
/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill
方式二 · CLI 安裝到使用者層級
npx ui-ux-pro-max-cli
uipro init --ai claude --global
⚠️ npm 套件名是 ui-ux-pro-max-cli，舊的 uipro-cli 已經不維護，別裝到那個。
確認裝成功

Skill 目錄裡有一支搜尋腳本，直接跑：

測試搜尋腳本
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "glassmorphism" --domain style
有回傳結果就是裝好了。找不到 python3 就換 python 或 py -3。
怎麼用

它會在你提到 UI 工作的時候自動觸發，講白話就好：

基本用法
幫我做一個個人品牌的 landing page，
產品是 AI 工作流線上課，
受眾是 25 到 40 歲的內容創作者，
風格要暖色系、有編輯感、不要科技藍。

想更精準，先叫它產一份設計系統再開工：

先產設計系統
先幫我生一份完整的 design system：
主色、輔色、CTA 色、背景、文字、邊框，
加上一組字體配對（標題用襯線，內文用無襯線），
確認之後再開始寫 code。
拿到 design system 之後存成 DESIGN.md 放進專案根目錄，後面每次改都會延用同一套，不會每次生成都跑掉。
⚠️ 版本更新頻繁，內建的風格數量、配色數量一直在變。不要在自己的內容裡引用它的具體數字，會過期。
04Task Observer · 在背景優化其他 Skill
解決什麼：你每天都在糾正 Claude。「這個標籤要靠左」「這種句型不要用」「檔名要照這個規則」。但這些糾正下次開新 session 就消失了，你隔天再講一次。Task Observer 把這些糾正記下來，整理成其他 Skill 的修改提案，你定期審一次，把它套用回去。
安裝
clone 並取出子資料夾
mkdir -p ~/.claude/skills
cd ~/.claude/skills
git clone https://github.com/rebelytics/one-skill-to-rule-them-all.git temp-tos
mv temp-tos/task-observer ./task-observer
rm -rf temp-tos
⚠️ 注意保留 references/ 子資料夾，缺了它會不完整。
關鍵步驟：加啟動指令
⚠️ 這一步不做的話，這個 Skill 幾乎不會觸發。光靠 description 自動比對不夠可靠。

打開你的 CLAUDE.md（沒有就在專案根目錄建一個），加上這段：

CLAUDE.md 加入段落
## 工作階段規則
任何會用到工具並產出成果的任務，開始之前先呼叫 task-observer skill。
載入任何 skill 的時候，檢查 observation log 裡有沒有標記到該 skill 的 OPEN 觀察。
有的話直接把那些洞見套用到當前工作，不用等 skill 檔案更新。
確認裝成功

跑一個多步驟任務，中間刻意糾正 Claude 兩次（例如「這個格式我要改成 A 不要 B」）。任務結束後問它：

測試指令
這次 session 有記錄到什麼 observation 嗎？

它應該要列出剛剛捕捉到的內容。

觀察日誌長什麼樣
兩個位置
skill-observations/    ← 捕捉到的觀察
skill-updates/         ← 提出的修改提案
平常不用自己去翻，Claude 會處理。想確認它有沒有在做事的時候再打開看。
建議的複習節奏

排固定時段，一週一到三次，開一個 session 專門處理：

複習節奏指令
把 observation log 裡所有 OPEN 狀態的觀察列出來，
逐一告訴我它建議改什麼、改在哪個 skill、為什麼。
我確認之後你再套用。
建議排週一早上，一次大概 15 分鐘。
⚠️ 它不會自己動手改你的 Skill。它記錄、它提案，套用需要你點頭。這是安全設計，不是缺點。看到「完全自動優化、你什麼都不用做」的說法，那個是誇大。
05Find Skills · 幫你找下一個該裝的
解決什麼：公開的 skill 市集已經上萬個，翻不完。而且品質落差極大，有些是幾十次安裝的實驗品。Find Skills 幫你搜、幫你比對來源可信度、幫你裝。
安裝
安裝
npx skills add vercel-labs/skills --skill find-skills --agent claude-code
基本指令
搜尋、安裝、更新
# 搜尋（互動式或帶關鍵字）
npx skills find [關鍵字]

# 限定某個 owner 底下搜
npx skills find [關鍵字] --owner [owner名稱]

# 安裝
npx skills add [owner]/[repo] --skill [skill名稱] --agent claude-code

# 檢查有沒有更新
npx skills check

# 全部更新
npx skills update
怎麼用

裝完之後直接跟 Claude 講你要做什麼：

請它幫你找 Skill
我要做一個每週自動整理 IG 貼文數據並產出報表的流程，
幫我找有沒有現成的 skill 可以用，
列出來的時候告訴我每個的安裝數跟來源。

它會去搜，然後把結果連同可信度資訊一起給你。

它內建的把關標準

它的 SKILL.md 裡明確寫著：不能只憑搜尋結果就推薦，必須先驗證三件事。

檢查項標準
安裝數優先選 1K 以上，100 以下要非常小心
來源信譽官方來源（vercel-labs、anthropics、microsoft）優於不明作者
GitHub stars回頭看原始 repo 的狀況

⚠️ 裝任何第三方 Skill 之前，自己打開 SKILL.md 看一遍。Skill 本質上是會被注入你 context 的指令文字，來源不明的東西不要照單全收。這件事沒有工具可以完全代勞。

分兩層檢查。

第一層，檔案在不在對的位置。

ls ~/.claude/skills/

第二層，Claude 有沒有讀到。直接問它：

Skill 有時候會觸發，有時候不會
SKILL.md 開頭的 frontmatter 裡有一段 description，Claude 靠它判斷要不要載入。寫得太抽象就會漏。打開檔案，把 description 改成使用者實際會講的話。
✕ 改前description: 提升文字品質與可讀性的寫作輔助工具
✓ 改後description: 移除文字中的 AI 寫作痕跡。當使用者要求寫文案、寫貼文、寫文章、改稿、潤稿、或說「這段讀起來很 AI」「幫我改得像人寫的」「去掉 AI 味」時，一律使用此 skill。
差別在於：改後的版本包含了實際會出現的動詞跟說法。要更保險，就在 CLAUDE.md 直接寫死觸發條件，跟 Task Observer 那節的做法一樣。
裝太多 Skill 會不會拖慢速度？
會，但拖慢的是 context 而不是速度。每個載入的 Skill 都佔 context 空間，佔越多，留給當前任務推理的空間越少。建議：使用者層級只放每天都用的三到五個，其他全部丟專案層級，用到再說。
怎麼移除？
Skill 直接刪資料夾：
移除 Skill
rm -rf ~/.claude/skills/[skill名稱]
Plugin 走 /plugin 介面移除，或依照該 plugin 自己的 uninstall 指令。刪完重啟 Claude Code。

# 品牌語氣過濾器

## 什麼時候用
- 產出任何要對外發布的文字之前
- 使用者要求檢查既有文案
- 使用者說「讀起來怪怪的」

## 語氣原則
- 直接、清楚、中性教學
- 不煽情、不說教
- 用具體細節取代抽象形容

## 禁用句型
1. 對比轉折：「不是……而是……」「不只是……更是……」
2. 昇華總結：「真正的 X，是……」「這才是 X 的本質」
3. 號召激勵：「現在就開始……」「是時候……了」
4. 萬用過渡：「這讓我想到……」「值得注意的是……」
5. 假設共鳴：「你是否曾經……」「很多人都……但其實……」

## 替代寫法
遇到對比或轉折，改用兩句短句並排，中間不加轉折詞。

錯誤：不是工具不夠強，而是你沒有系統。
正確：工具夠強。沒有系統，一樣做不出東西。

錯誤：這不是在浪費時間，這是在建立系統。
正確：同樣的任務，下週你只需要 10 分鐘。
