01claude-video · 讓 Claude 真的看得懂影片
repo bradautomates/claude-video指令 /watch
解決的問題：Claude 沒辦法看影片。丟一個 YouTube 連結給它，它只能從標題猜，或抓一份缺了大半畫面資訊的逐字稿。
它做了什麼
先抓字幕（大多數公開影片有字幕，這段免費）
只下載需要的片段
抽出畫面 frames（場景感知抽取，或用 efficient 模式快速抽關鍵影格）
產出帶時間戳的逐字稿（沒字幕時才用 Whisper API 補）
把每一張 frame 當成圖片讀進去
跑完之後，Claude 是真的「看過畫面、聽過聲音」才回答。
安裝
Claude Code（建議，會自動更新）
/plugin marketplace add bradautomates/claude-video
/plugin install watch@claude-video
Codex、Cursor、Copilot、Gemini CLI 等 50+ host
npx skills add bradautomates/claude-video -g

-g 是全域安裝，所有專案都能用，拿掉就是只裝在當前專案。
claude.ai 網頁版：到 repo 的 Releases 頁下載 watch.skill，Settings → Capabilities → Skills → + 上傳。

怎麼用
三種用法
/watch https://youtu.be/xxxxx 這支影片的開場鉤子是怎麼設計的？

/watch bug-repro.mov 這段錄影裡出了什麼問題？

/watch https://youtu.be/xxxxx 幫我總結，跳過行銷話術，只講實際更新了什麼
自媒體實際用途
  • 拆解對標帳號的影片：問它開場前三秒做了什麼、剪輯節奏怎麼安排、資訊密度分布
  • 分析廣告素材：競品的 Reels 為什麼留得住人
  • 翻譯 ＋ 重製：看完英文影片直接產出中文腳本
  • 自己影片的檢討：把成品丟進去，讓它從觀眾視角挑問題
⚠️ 要注意：需要 yt-dlp 和 ffmpeg（macOS 首次執行會用 brew 自動安裝，Linux 和 Windows 會印出指令要你自己跑）。影片沒有字幕時才需要 Whisper API key，會產生額外費用。抽 frames 會吃 context，長影片建議先用 efficient 模式。
02graphify · 讓 Claude 記得住你的專案
repo Graphify-Labs/graphify指令 /graphify
解決的問題：Claude Code 每開一個新 session，就把你的專案重新 grep 一遍。上一次理解的結構，這一次不算數。
它做了什麼

讀過你指定的資料夾之後，建出一張知識圖譜存起來。之後 Claude 用「走訪圖譜」取代「每次重新搜尋檔案」。支援的格式不只程式碼：PDF、Markdown、截圖、圖表、白板照片都吃得下，用 Claude 的視覺能力抽取概念和關聯，全部連進同一張圖。

官方 README 標示的效益是每次查詢的 token 用量約為直接讀原始檔案的 1/71.5。
安裝（需要 Python 3.10+）
標準安裝
pip install graphifyy && graphify install
⚠️ 注意套件名稱：PyPI 上目前叫 graphifyy（兩個 y），因為 graphify 這個名字還在申請回收中。CLI 指令和 skill 指令本身仍然是 graphify。
pip 失敗時（macOS Homebrew Python 或 Debian/Ubuntu 會擋）
pipx install graphifyy

Windows 裝完找不到指令：把 Python Scripts 資料夾加到 PATH，路徑是 %APPDATA%\Python\Python3xx\Scripts（3xx 換成你的版本）。或直接用 pipx，它會自動處理 PATH。

怎麼用
在任何資料夾開 Claude Code 後執行
/graphify .
產出檔案內容
graph.html可互動的圖譜，點節點、搜尋、依社群篩選
obsidian/可以直接用 Obsidian 打開的 vault
wiki/維基百科式文章，給 agent 導航用（加 --wiki 才產生）
GRAPH_REPORT.md樞紐節點、意外的關聯、建議的提問方向
graph.json持久化圖譜，幾週後還能直接查，不用重跑
cache/SHA256 快取，重跑時只處理有變動的檔案
自媒體實際用途

程式碼專案以外，這個工具對內容創作者的價值在素材庫：

  • 把過去所有貼文、腳本、筆記丟進一個資料夾跑一次，讓 Claude 之後寫新內容時能引用自己的舊素材
  • 把研究資料、PDF、截圖整理成一張圖，寫深度內容時直接查
  • GRAPH_REPORT.md 會標出「意外的關聯」，這個常常直接就是選題
⚠️ 要注意：首次跑大型資料夾會花時間，也會消耗 API 額度。圖譜品質取決於原始素材的結構，一堆無標題的散檔效果有限。README 有明確說明它會區分「找到的」和「推測的」內容，別把推測部分當成事實引用。
03notebooklm-py · 把研究外包出去，省下 context
repo teng-lin/notebooklm-pyPyPI notebooklm-py授權 MIT
解決的問題：深度研究會燒光你的 context window。查十篇資料，context 就滿了，真正要做的事反而沒空間。
它做了什麼

NotebookLM 的非官方 Python API ＋ agent skill。讓 Claude 把研究工作丟給 Google 的統整引擎去做，只把結論拿回來。功能覆蓋比網頁介面更廣，包含網頁 UI 沒有開放的能力。

產品更名注意Google 在 2026 年 7 月把 NotebookLM 改名為 Gemini Notebook。它仍然是同一個獨立產品（現在 Gemini app 裡也能用），舊連結會自動轉址，這個套件驅動的是同一個底層服務，功能不受影響。套件名稱維持 notebooklm-py。
安裝（最快的方式）
CLI 使用者與 AI agent
uv tool install "notebooklm-py[browser]"
# 或：pipx install "notebooklm-py[browser]"

notebooklm login
# 首次執行會自動下載 Chromium（約 170 MB），然後 Google 登入

notebooklm auth check --test --json
# 驗證用，看到 "status": "ok" 就成功了
為什麼用 uv tool 或 pipx：它們會把 CLI 裝在獨立環境並加進 PATH，不會跟其他工具的依賴打架。而且在新版 macOS（Homebrew Python）和 Debian/Ubuntu 上，系統層級的 pip install 會被 PEP 668 擋掉，這兩個工具不會有這個問題。
還沒裝 uv
curl -LsSf https://astral.sh/uv/install.sh | sh
# 或：brew install uv
# Windows：winget install astral-sh.uv
要用 pip 也可以，但要在 virtualenv 裡
python3 -m venv .venv && source .venv/bin/activate
# Windows：.venv\Scripts\activate
pip install "notebooklm-py[browser]"
三種登入方式
方式適用情境
Playwright 互動登入（預設）本機開發
從已登入的瀏覽器匯入 cookie不想裝 Playwright
Master token伺服器、CI、遠端 MCP connector，會自動處理過期 session

支援多帳號 profile 切換，不用重複登入。

自媒體實際用途
  • 選題資料庫：把整個領域的資料丟進一個 notebook，每次要寫新內容就 ask 一次，拿到帶引用來源的答案
  • 跨 session 記憶：維護一個「主腦」notebook，每次工作結束把決策和修正存成 note，下次開工先 ask 一次
  • 自動產生 podcast：generate audio 搭配排程，把研究成果做成音檔
  • 查自己的筆記：把幾年份的日記、會議記錄丟進去，拿到跨時間、有引用的答案
⚠️ README 有明確的風險警告：這是非官方套件，使用的是 Google 未公開文件的內部 API，與 Google 沒有任何合作關係。API 隨時可能失效，Google 改內部端點不會通知。有速率限制，大量使用會被限流。官方建議用在原型、研究、個人專案，不要放進正式營運系統。每個 notebook 能放的來源數量取決於你的 Google 帳號等級。
04impeccable · 讓 AI 做的介面不再千篇一律
repo pbakaus/impeccable指令 /impeccable文件 impeccable.style
解決的問題：所有 AI 生出來的前端長得都一樣。Inter 字體、紫到藍的漸層、卡片裡面包卡片、彩色底配灰字、每個標題上面一顆圓角方塊 icon。
它做了什麼

給 AI coding agent 用的設計指引。內容包含 1 個 skill、23 個設計指令（建立你和 AI 之間的共同設計語彙）、60 條決定性偵測規則，加上需要 LLM 判斷的評論檢查，以及瀏覽器即時迭代功能。

CLI 和瀏覽器外掛跑那 60 條規則時不需要 LLM、不需要 API key，純靠規則判斷。Impeccable 是從 Anthropic 官方的 frontend-design skill 出發做的擴充。
✎ 訂正一個流傳的數字網路上流傳的版本寫「45 個反模式偵測器」，官方 README 的實際數字是 60 條。23 個指令這個數字是對的。
安裝
在專案根目錄執行
npx impeccable install
然後在 AI coding 工具裡
/impeccable init

init 會問你這個介面屬於品牌類（行銷頁、landing page、作品集）還是產品類（app UI、儀表板、工具），然後寫出 PRODUCT.md 和 DESIGN.md，記錄受眾、品牌定位、語氣、反面參考、色彩、字體、元件。之後所有指令都會讀這兩個檔案。

05ponytail · 讓 Claude 少寫你沒要求的程式碼
repo DietrichGebert/ponytailnpm @dietrichgebert/ponytail授權 MIT支援 20 種 agent
解決的問題：Claude 會過度工程。多裝一個依賴、多寫一層 boilerplate、多做兩個你根本沒要求的功能。
它做了什麼：懶惰階梯

在寫程式之前，agent 會沿著一組階梯往下走，停在第一個成立的階：

Laziness Ladder（7 階）
1. 這個東西需要存在嗎？      → 不需要就跳過（YAGNI）
2. 這個 codebase 裡已經有了嗎？ → 有就重用，不要重寫
3. 標準函式庫做得到嗎？        → 用它
4. 平台原生功能做得到嗎？      → 用它
5. 已安裝的依賴做得到嗎？      → 用它
6. 一行能解決嗎？             → 就一行
7. 都不行，才寫最小可行的版本
✎ 訂正一個流傳的數字網路上流傳的版本寫成 5 階（跳過 → 重用 → stdlib → 依賴 → 寫），官方 README 是 7 階，中間還有「平台原生功能」和「一行能解決嗎」兩層。
重要的是這個階梯跑在理解問題之後，不是取代理解。它會先讀懂改動會碰到的程式碼、追過真實的執行流程，才決定停在哪一階。README 的原話是：對解法懶惰，對閱讀絕不懶惰。
安全性不在刪減範圍內。信任邊界驗證、資料遺失處理、資安、無障礙，這四項永遠保留。
實測數據（官方 README）
指標相對於無 skill 的 baseline
程式碼量少約 54%（最高可到 94%）
成本便宜約 20%
速度快約 27%
安全性100% 維持

測試條件（這段很重要，別漏掉）：

  • 在真實的開源專案上測（FastAPI + React），用真實的 Claude Code session
  • 對照組是同一個 agent，不裝 skill
  • 54% 是 12 個功能任務的平均值，模型是 Haiku 4.5，n=4
  • 在 agent 容易過度建構的情況（例如做日期選擇器）可以到 94%，程式碼本來就精簡的情況接近 0%
  • 早期單次測試曾報過 80–94%，官方後來說明：對照公平的 agentic baseline 之後，那是單一任務的上限值，不是平均值
✎ 訂正一個流傳的數字網路上流傳的版本寫 n=8，官方 README 是 n=4。這是小樣本測試，數字當參考，不要當保證。
⚠️ README 有一個誠實的但書：這個 skill 不是「用最少 token」。降低成本和延遲是遵循階梯的副作用。在某些會花大量思考 token 反覆推敲階梯的推理模型上（README 點名 GPT-5.5），成本反而會往上跑。

Part 2 · Claude Code 上手指南

從零安裝
到跑第一個專案

Claude Code 是 Anthropic 的 agentic coding 工具，跑在終端機、桌面 app 或編輯器裡。它能讀你的檔案、寫程式、跑指令、操作 git。上面 5 個 repo 有 4 個是以 Claude Code plugin 或 skill 的形式安裝的，所以這是前置條件。

前置需求
  • 帳號：Claude Code 需要付費方案。Claude Pro、Max、Team、Enterprise，或有 API 額度的 Anthropic Console 帳號都可以。免費版的 claude.ai 不包含 Claude Code。
  • 作業系統：macOS、Windows、Linux 都支援，Windows 也可以用 WSL。
  • Node.js：官方建議的原生安裝方式不需要 Node.js，只有走 npm 安裝才需要（v2.1.198 之後要 Node.js 22 以上）。不過 ponytail 和 claude-video 有用到 Node，建議還是裝一個。
安裝三種安裝方式
原生安裝（官方建議）· macOS / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash
原生安裝 · Windows（PowerShell）
irm https://claude.ai/install.ps1 | iex

安裝完成後 binary 在 ~/.local/bin/claude，會在背景自動更新。

Homebrew（不會自動更新）
brew install --cask claude-code
npm（需要 Node.js 22+）
npm install -g @anthropic-ai/claude-code
⚠️ 永遠不要加 sudo。這是官方明確的警告，加了會製造之後的權限問題。
驗證確認裝好了沒
驗證安裝
claude --version
claude doctor

claude doctor 會告訴你目前是哪一種安裝方式、有沒有問題。
出現 command not found，代表 ~/.local/bin 不在你的 PATH 上。

轉移從 npm 版轉到原生版

在 Claude Code 裡跑 /migrate-installer，或在終端機跑 claude install。然後：

清掉舊的 npm 版
npm uninstall -g @anthropic-ai/claude-code
hash -r
hash -r 是讓舊的 npm binary 不要繼續蓋掉新的。設定檔（~/.claude/settings.json）和專案設定（.claude/）在轉移過程會保留。
CLAUDE.md：最該先做的一件事

放在專案根目錄的 markdown 檔，用來告訴 Claude Code 這個專案的技術棧、慣例、常用指令。每次開 session 它都會讀。

在 Claude Code 裡執行，自動生初版
/init
這一步的效果比多數人想像的大
寫清楚「這個專案用什麼」「不要動哪些檔案」「commit 訊息格式」，之後每一次對話都省掉重複解釋。非工程用途也一樣——如果你用 Claude Code 管理內容素材庫，CLAUDE.md 就寫你的品牌語氣、禁用句型、檔案命名規則。
常用指令
指令功能
/help列出所有可用指令（版本會更新，以這個為準）

控制成本的四個習慣
善用 /clear。對話越長，每次請求送出的 context 越多，成本越高。換題目就清掉。
長對話用 /compact。保留結論，丟掉過程。
簡單任務切小模型。用 /model 換，重構、規劃這種才需要最強的。
寫好 CLAUDE.md。前置說明寫一次，勝過每次對話重複解釋。
裝上面的 ponytail 也算第五招，官方數據是成本降約 20%。
Plugin 和 Skill 的差別
  • Skill 是一份指示文件（SKILL.md），告訴 Claude 在特定情況下該怎麼做事。單純的知識和流程。
  • Plugin 是一個包裝，裡面可以包含 skill、指令、hook、MCP server 設定。透過 marketplace 安裝，可以自動更新。
上面 5 個 repo 裡：ponytail 和 claude-video 走 plugin marketplace；graphify 和 notebooklm-py 走 Python 套件 ＋ skill 安裝；impeccable 走 npx。
npx skills add 這個指令來自 Agent Skills 生態（agentskills.io），能把 skill 裝進它偵測到的所有 agent，不限於 Claude Code。
