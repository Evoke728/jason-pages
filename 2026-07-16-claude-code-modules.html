1 · 心智模型

你到底
在操作什麼

多數人打開 Claude Code，做的第一件事是打字聊天。問一個問題，得到一段回答，複製，貼到自己的檔案裡。這是把一台代理人當成聊天視窗在用。

Claude Code 的設計是代理人（Agent）。你給它一個目標，它自己讀檔案、自己執行指令、自己看錯誤訊息、自己修好、自己交件。過程中你不需要複製貼上任何東西。

差別在一句話
聊天機器人給你答案，代理人給你結果。
四個模組

代理人之所以能做到這件事，是因為它有四個模組。這四個模組每一次都在，你用不用是另一回事。

一個具體的對照
聊天機器人的做法
你：幫我把這三十篇文章的重點整理成表格
它：好的，請把文章內容貼給我
你：（開始複製第一篇……第二篇……第三篇……）
代理人的做法
你：讀 ./articles/ 資料夾裡的三十個 md 檔，抓出每篇的核心論點、目標讀者、可複用的鉤子，整理成一張表格，輸出成 summary.md
它：（自己讀完三十個檔案，自己寫檔，自己存好）完成，三十篇都在 summary.md 裡
第二種做法，你打字的時間是 十五秒。
2 · 開始之前

安裝
與五種介面

你需要：一個付費的 Claude 訂閱（Pro 或 Max）或 Anthropic Console 帳號，以及一台電腦（macOS、Windows、Linux 都可以）。

安裝四種裝法，挑一個
macOS / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash
Windows（PowerShell）
irm https://claude.ai/install.ps1 | iex
Homebrew（macOS）
brew install --cask claude-code
WinGet（Windows）
winget install Anthropic.ClaudeCode
裝完之後，進到任何一個資料夾
cd 你的專案資料夾
claude
第一次會要你登入。登入完就可以開始。
介面五種介面，同一個引擎

很多人以為 Claude Code 只能在終端機用。它有五種介面，共用同一套設定、同一份 CLAUDE.md、同一組 MCP 連接。

介面適合誰特點
終端機 CLI想要完整功能的人功能最全，可串接、可寫進腳本
VS Code 外掛已經在用 VS Code 的人有視覺化的修改對照
JetBrains 外掛IntelliJ、PyCharm 使用者需另外裝 CLI
桌面應用程式不想碰終端機的人視覺化介面，可同時跑多任務、可排程
網頁版想在瀏覽器或手機上跑的人不用安裝，可跑長任務
給非工程師的建議：直接用桌面應用程式。介面友善，不用碰指令列，四個模組一樣都有。等你熟了再考慮終端機。
3 · 模組一｜檔案

你的檔案系統
就是它的工作區

你打開 Claude Code 的那個資料夾，就是它的視野範圍。它看得到裡面每一個檔案，讀得到、改得到、也能新建。

方向搞反了
還在手動上傳檔案？檔案已經在你電腦裡，它住在裡面。
  • 一百份 PDF 放在一個資料夾，你可以叫它全部讀完再摘要
  • 一團亂的下載資料夾，你可以叫它照規則重新分類命名
  • 三十篇部落格草稿，你可以叫它統一語氣、統一格式
  • 一份 CSV，你可以叫它清資料、算數字、畫圖、輸出報表
建立你的工作資料夾

不要在桌面亂丟。開一個乾淨的專案資料夾：

建議結構
my-content/
├── CLAUDE.md          ← 記憶檔（下一節會講）
├── drafts/            ← 草稿
├── published/         ← 已發布
├── research/          ← 素材與參考資料
└── output/            ← Claude 產出的東西
四個立刻可用的指令
指令 1 · 讀完 PDF 出表格
讀 research/ 資料夾裡所有的 pdf，每份抓出三個核心論點，
整理成一張表格，欄位是：檔名 / 論點一 / 論點二 / 論點三 / 我可以用的角度，
輸出成 output/research-summary.md
指令 2 · 找出重複主題
把 drafts/ 裡的所有檔案讀過一遍，找出重複講過的主題，
列出哪些可以合併，哪些可以拆成系列。不要動原檔。
指令 3 · 整理下載資料夾
整理 ~/Downloads 資料夾。依照檔案類型與日期分類到子資料夾，
重新命名成「YYYY-MM-DD_原始檔名」的格式。
執行前先列出你打算怎麼做，等我確認。
指令 4 · 分析你的寫作習慣
讀 published/ 裡所有已發布的文章，分析我的寫作習慣：
常用句型、平均段落長度、開頭的模式、收尾的模式。
輸出成 output/writing-style.md
⚠️ 一個重要的安全習慣：在指令最後加一句「執行前先列出計畫，等我確認」。這一句會讓它先講清楚要做什麼，你點頭它才動手。批次改檔名、批次刪檔、大規模重構之前，這一句是必要的。
4 · 模組二｜指令

你的終端機
是它的手

它能執行指令，讀取結果，看到錯誤訊息，然後自己修好，再跑一次。這個「執行 → 失敗 → 讀錯誤 → 修正 → 再執行」的迴圈，全程不需要你介入。

你不需要會寫程式
你描述，它執行。你只需要描述你要的結果——要用什麼工具、裝什麼套件、指令怎麼下、跑錯怎麼修，那些是它的工作。
非工程師也能跑的四個任務
批次處理圖片
把 images/ 資料夾裡所有的 png 轉成 jpg，
寬度統一縮到 1080，品質 85，
輸出到 images-web/ 資料夾，原檔保留。
需要什麼工具自己裝。
影片轉逐字稿
把 videos/ 裡的所有 mp4 抽出音軌，
用 whisper 轉成逐字稿，輸出成同名的 txt 檔。
跑完之後告訴我每支影片的長度和字數。
資料清理
讀 data/sales.csv。
清掉重複列，把日期格式統一成 YYYY-MM-DD，
金額欄位的逗號和貨幣符號拿掉轉成數字，
空值填 0。
輸出成 data/sales-clean.csv，另外告訴我清掉了幾筆、改了幾筆。
把重複工作變成腳本
每次我寫完一篇文章，我都要做這四件事：
1. 檢查錯字
2. 把標題改成 60 字以內
3. 生三個 IG 版本的鉤子
4. 存到 published/ 並加上日期
幫我把這個流程寫成一個腳本，之後我只要給你檔名就能跑完。
無介面模式（進階但很有用）

Claude Code 可以完全不進入對話介面，直接在指令列跑完一件事：

直接跑完一件事
claude -p "讀 sales.csv，告訴我這個月營收比上個月成長幾 %"
把其他工具的輸出餵給它
tail -200 app.log | claude -p "看一下這些 log 有沒有異常"
這個用法的價值在於：你可以把它寫進自動化腳本裡，變成每天早上自動跑的東西。

5 · 模組三｜記憶

CLAUDE.md
完整指南

沒有記憶，就沒有連續性。沒有連續性，你每一次對話都要重講一遍背景——你是誰、你在做什麼、你的偏好是什麼、上次的決定是什麼。

投報率最高的一個模組
每次從零開始，一半的時間都在重講背景。這是四個模組裡最多人沒開過的一個，也是投報率最高的一個。
CLAUDE.md 是什麼

在你的專案資料夾根目錄放一個叫 CLAUDE.md 的檔案。Claude Code 每次啟動都會自動讀完它，然後才開始工作。
它不是文件，是設定檔。你在裡面寫的每一條規則，都會變成它的預設行為。

# 個人偏好

## 關於我
- 我是內容創作者，不是工程師。
- 我的主力平台是 Instagram 與 Threads，內容主題是 AI 工具與自媒體。
- 我用繁體中文（台灣用語）。

## 回答方式
- 直接給結論，不要鋪陳。
- 需要我做決定的時候，給我 2–3 個選項和各自的取捨，不要只給一個。
- 技術名詞第一次出現時用一句話解釋，之後直接用。
- 不確定的事情直接說不確定，不要猜。

## 執行規則
- 動到檔案之前，先列出你要做什麼，等我確認。
- 批次操作（改名、刪除、覆寫）一律先確認。
- 產出的檔案放到 output/ 資料夾。

## 語氣
- 中性、清楚、可以直接套用。
- 不要用「不是 A 而是 B」這種對比句型。
- 不要勵志收尾。

# 專案：IG 內容工廠

## 這個專案在做什麼
生產 Instagram 輪播貼文與 Threads 短文。
每一則貼文包含：輪播文案、生圖 prompt、IG 說明文案、Threads 文案。

## 資料夾結構

- drafts/ — 草稿

- 帳號：@jasonxtsai

- 每則 7–10 張
- 第一張是鉤子，最後一張是 CTA

自動記憶

除了你寫的 CLAUDE.md，Claude 在工作過程中也會自己記東西——它發現的模式、你糾正過的地方、專案的慣例。這部分它自己維護，你不用寫。想看它記了什麼、或想刪掉錯的，用 /memory。

6 · 模組四｜工具

MCP、Skills
Hooks

前三個模組讓它在你的電腦裡工作，這一個讓它走出你的電腦。這是四個模組裡最容易被低估的一個。

MCP：把外部服務接進來

MCP（Model Context Protocol）是一個開放標準，用來把 AI 工具連上外部資料來源。接上之後，Claude Code 可以讀你 Google Drive 的文件、更新 Jira 任務、從 Slack 抓對話、查資料庫、讀寫 Notion。

一句話跨三件事
去我 Notion 的「內容行事曆」資料庫，
把這週狀態是「草稿」的項目全部列出來，
每一個都幫我補上鉤子跟大綱，寫回 Notion。
這一句跨了三件事：讀 Notion、生成內容、寫回 Notion。全程你沒有離開對話框。
Skills：把工作流存起來

Skill 是一個可重複使用的工作流。你把一套做事的方法寫下來，之後用一個指令就能叫出來。
舉例：你每次做輪播，流程都固定——分析素材、決定張數、寫文案、生 prompt、寫說明文案。把這套做成 Skill，之後你只要說「用輪播流程處理這篇文章」，它就照著跑完整套。

Skill 跟一般 prompt 的差別：prompt 是一次性的，Skill 是存起來的。你不用每次都重打。
Hooks：自動觸發

Hook 讓你在 Claude Code 做某件事的之前或之後，自動跑一個指令。例如：改完檔案自動格式化、寫完文章自動備份、要刪檔案先跳確認。

層級差在哪
CLAUDE.md 是規則，Hook 是強制執行。這是「把規矩變成機制」的層級。
層級你做什麼它幫你做什麼
MCP接上服務讀寫外部資料
Skills存下流程重複執行同一套方法
Hooks設定觸發條件自動執行前置／後置動作
子代理給它一個大任務拆成好幾個代理人平行跑

- 禁用句型：「不是 A 而是 B」、「真正的 X 是」、「現在就開始」
- 對比用兩個短句並排，不用轉折詞
- 每個版本要標明它在追求什麼（清楚 / 情緒 / 好奇）
指令 · 三版本改寫
讀 output/writing-style.md（我的寫作風格分析）。
用這個風格，把 drafts/新文章.md 改寫成三個版本：
版本 A：追求清楚，最短
版本 B：追求好奇心，鉤子最強
版本 C：追求說服力，論證最完整
每個版本後面標註它犧牲了什麼。

- 分不清事實和推論的時候，明講哪個是哪個
- 找不到證據的時候直接說找不到，不要補

輸出成 output/文獻整理.md

9 · 三十天上手路徑

不要一次全開
照順序來

W1第一週｜檔案 · 讓它讀得到你的東西
  • Day 1：安裝，開一個乾淨的專案資料夾
  • Day 2：把你的素材、草稿、參考資料丟進去，分類好
  • Day 3：叫它讀完整個資料夾，給你一份摘要
  • Day 4：叫它整理你最亂的一個資料夾
  • Day 5：叫它分析你已發布的內容，找出你的寫作模式
這週結束時你會理解：它看得到你的東西，你不用上傳。
W2第二週｜記憶 · 停止重講背景
  • Day 8：用 /init 生成第一份 CLAUDE.md
  • Day 9：手動改寫，寫進你的品牌設定、語氣規則、禁用句型
  • Day 10：建立 ~/.claude/CLAUDE.md，寫進你的個人偏好
  • Day 11：實測——開一個全新對話，看它記不記得你的規則
  • Day 12：把不管用的規則改得更具體
這週結束時你會理解：好的 CLAUDE.md 值一小時，能省你幾十小時。
W3第三週｜指令 · 讓它動手，不只動嘴
  • Day 15：叫它幫你批次處理一次圖片
  • Day 16：叫它清一份 CSV
  • Day 17：叫它把你每週的重複工作寫成一個腳本
  • Day 18：跑那個腳本，看能不能省時間
  • Day 19：改進那個腳本
這週結束時你會有：至少一個能自動跑的流程。
W4第四週｜工具 · 走出你的電腦
  • Day 22：接一個 MCP（建議從 Notion 或 Google Drive 開始）
  • Day 23：做一個「讀外部資料 → 生成 → 寫回去」的完整循環
  • Day 24：把你最常做的流程做成一個 Skill
  • Day 25：用那個 Skill 跑一次真實任務
  • Day 26：回頭改進 CLAUDE.md，把這個月學到的規則寫進去
週末：檢視這一個月省下多少時間。
10 · 九個最常見的錯誤

卡住的時候
回來翻這裡

把它當聊天機器人
症狀：一直問問題、複製答案、貼到別的地方。
修正：給它目標和輸出位置，讓它自己交件。
沒有 CLAUDE.md
症狀：每次都要重講你是誰、你要什麼。
修正：花一小時寫一次，之後每一次對話都省十分鐘。
CLAUDE.md 寫太長
症狀：寫了五百行，它還是不照做。
修正：砍到 200 行以內，只留最關鍵的規則。
規則寫得太抽象
症狀：寫「文案要有質感」，它給你的東西還是一樣。
修正：改成「IG 說明文案 100–180 字，禁用『不是 A 而是 B』句型」。
資料夾一團亂
症狀：它讀了一堆不相干的東西，回答歪掉。
修正：一個專案一個資料夾，結構清楚。它的視野就是你的資料夾。
一次給太多任務
症狀：它做了一半，或每件事都做得很淺。
修正：一次一個目標。做完再給下一個。
沒有要求它先講計畫
症狀：它動了你不想讓它動的檔案。
修正：批次操作前，一律加「先列出計畫，等我確認」。
不驗證產出
症狀：它給的數字是錯的，你直接發出去了。
修正：任何要對外發布的數據、引用、連結，自己再確認一次。
學了不用
症狀：看完教學，覺得很酷，然後關掉。
修正：現在就挑一個你這週要做的重複工作，丟給它。
