01scroll-world · 把品牌變成可以捲動穿越的 3D 世界要付費
它解決什麼問題：你看過 Apple 產品頁那種效果嗎。滑鼠往下捲，鏡頭就往前飛，穿過一個場景進到下一個場景，中間完全沒有剪接痕跡。這種頁面過去要一組 3D 動態設計團隊做，報價六位數起跳。scroll-world 把整套流程包成一個 skill：訪談你的品牌 → 生成場景圖 → 生成鏡頭飛行影片 → 把捲動位置對應到影片時間軸 → 輸出可以直接放進任何網站的前端程式碼。輸出是框架無關的。

幫我做一個 scroll-through 的 3D 世界落地頁

接下來 Claude 會開始訪談你。這一段不要敷衍，它問的東西直接決定輸出品質。準備好這四個答案：

品牌是什麼，賣什麼——一句話講完
視覺方向——等距黏土泥塑風？超寫實建築攝影風？賽博龐克？這一句話的差異會讓整組場景長得完全不同

⚠️ 真實成本：這是整份手冊裡唯一要花錢的工具。一組六場景的完整輸出，上游大約需要十幾次付費生成。每次生成的單價依你選的後端與模型而定，官方 repo 的 README 有寫明計費方式。建議先跑三場景的縮小版測試，確認風格對了再跑完整版。想先看效果再決定要不要花錢，repo 裡有兩個現成 demo 可以直接看。
什麼情況不要用

  • 你需要頁面內容常常更新。改一個場景等於重新生成一段影片
  • 你只想要一般的捲動動畫。那用 GSAP ScrollTrigger 就好，免費而且輕很多
02OmniRoute · 額度滿了自動跳下一家本體免費
它解決什麼問題：你正在跑一個很長的 Claude Code 任務，跑到一半跳出額度限制。任務中斷，上下文散掉，你要重來。

OmniRoute 是一個跑在你自己電腦上的 AI 閘道器，在你的工具跟各家 AI 供應商中間開一個 OpenAI 相容的 endpoint。核心機制是四層降級：訂閱額度 → API Key → 便宜模型 → 免費模型。前面那層滿了，毫秒內切到下一層，你的任務不會斷。
GitHub · diegosouzapw/OmniRouteMIT 授權
安裝
npm 全域安裝並啟動
npm install -g omniroute

omniroute
啟動後 API 跟儀表板會同時起來，都在 port 20128。儀表板網址：http://localhost:20128/dashboard
偏好容器化部署
docker pull diegosouzapw/omniroute
第一次怎麼跑
接上供應商。儀表板 → Providers。已有的訂閱走 OAuth 登入，有 API Key 的直接貼 Key。建議至少掛三層：一個付費主力、一個便宜備援、一個免費墊底
把工具指過去。在你的 IDE 或 CLI 裡把 base URL 改成下面那行，API Key 欄位隨便填一個字串就行，本機不驗證
設定降級順序。儀表板 → Combos，把供應商從最好的排到最便宜的
（選用）接成 MCP。讓 Claude Code 直接呼叫 OmniRoute 的工具集
base URL
http://localhost:20128/v1
接成 MCP
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
幾個實用細節
  • 儀表板會顯示每個模型剩餘的免費額度，這比自己記各家的重置時間實際得多
  • 內建 token 壓縮，透明作用在每個請求上，不需要改客戶端。程式碼區塊、URL、JSON 會被保護不動
  • 有內建的 log 儀表板，request、proxy、audit、console 四個分頁，debug 的時候很好用
⚠️ 真實成本：OmniRoute 本體免費開源，但要注意兩件事。第一，免費層的額度數字會變，各家供應商隨時可能調整或關閉免費方案，repo 裡的 docs/reference/FREE_TIERS.md 有維護一份現況表，看那份比看任何二手文章準。第二，掛上付費 API Key 之後就是真的在花錢，儀表板有預算控制跟成本追蹤，設定好上限再開始跑。
什麼情況不要用
  • 你只用一個供應商而且從來沒撞到額度。那多這一層只是多一個故障點
  • 你的工作流對延遲極度敏感。中間多一跳就是多一點延遲
  • 你在公司環境且有資安規範。這東西會經手你所有的 API Key，先問過再裝
03voicebox · 語音克隆、聽寫、TTS，全部跑在自己電腦上完全免費
它解決什麼問題：做 podcast、做短影音口播、或需要大量語音素材的人，過去只有兩個選擇：付月費給雲端服務，或接受品質差一截的本機方案。

voicebox 是本機優先的語音工作站。輸出端：7 個 TTS 引擎、23 種語言，零樣本克隆，幾秒鐘的參考音檔就能建出一個聲音檔案。輸入端：全域聽寫，在任何應用程式的任何輸入框裡按住熱鍵講話，放開之後逐字稿貼進游標所在位置。中間層：內建本機 LLM 潤稿。整個流程沒有一個位元組離開你的電腦。
GitHub官網 voicebox.shMIT 授權
安裝

一般使用者直接下載打包好的應用程式（voicebox.sh/download）。macOS 分 Apple Silicon 跟 Intel 兩個版本，Windows 是 MSI 安裝檔，有 NVIDIA 顯卡會自動設定 CUDA。

Linux 需要從原始碼建置
git clone https://github.com/jamiepine/voicebox.git
cd voicebox
just setup
just dev

# 沒裝 just 的話
brew install just
第一次怎麼跑
克隆你自己的聲音。準備一段 5 到 30 秒的乾淨錄音（沒有背景音樂、沒有環境噪音、沒有其他人講話）。錄音品質決定克隆品質，這件事沒有捷徑——用手機貼近嘴巴在安靜房間裡錄，效果會比用爛麥克風在有回音的空間錄好很多
設定全域聽寫。Settings → Dictation，開啟 Global Hotkey。macOS 預設是 Option + Space，需要授予「輔助使用」跟「輸入監控」兩個權限。Whisper 模型建議選 Turbo，速度跟準確度的平衡點最好
接上 Claude Code。REST API 在 http://localhost:17493，完整 API 文件在 /docs
用 curl 測一下生成
curl -X POST http://localhost:17493/generate \
  -H "Content-Type: application/json" \
  -d '{"text": "測試一下這個聲音", "profile_id": "你的profile_id", "language": "zh"}'
列出你所有的聲音檔案
curl http://localhost:17493/profiles
幾個實用細節
  • 多段參考音檔可以提升克隆品質。不要只丟一段，丟三段不同語氣的效果更好
  • Captures 分頁會保留每一次聽寫的原始音檔跟逐字稿，可以重跑不同大小的 Whisper 模型比較，也可以把任何一段 capture 直接升級成參考樣本
  • Voice Personality：可以幫每個聲音檔案寫一段人設描述，本機 LLM 會依照那個人設改寫你輸入的文字再唸出來
  • Apple Silicon 走 MLX 後端，推論速度比 PyTorch 快好幾倍
真實成本
零。模型下載完之後完全離線，沒有訂閱、沒有按字計費、沒有生成次數上限。唯一的成本是硬碟空間跟第一次下載模型的時間。
⚠️ 什麼情況不要用：你要克隆的不是自己的聲音——用別人的聲音做內容涉及肖像權跟聲音權，這是法律問題不是技術問題。另外，電腦很舊而且沒有獨立顯卡的話，純 CPU 推論會慢到不實用；需要即時串流語音的也不行，目前的架構是生成完再播放。
04cognee · 給 agent 一份關掉視窗也不會消失的記憶吃 token
它解決什麼問題：每次開新的 Claude Code session，你都要重新解釋一次專案結構、重新講一次你的偏好、重新貼一次上次的決策。

cognee 是一個記憶層，把你的文件、對話、決策紀錄，透過 ECL pipeline（Extract, Cognify, Load）處理成知識圖譜，存在你自己的機器上。跟一般向量檢索的差別在於它同時保留關聯性：純向量檢索能回答「這份文件講什麼」，知識圖譜能回答「哪個決定影響了哪個模組」這種需要跨越多個節點的問題。
GitHub官網Claude Code 整合
安裝
Python 套件，一行裝好
pip install cognee
本機儲存用的是 SQLite、LanceDB、Kuzu 三個輕量方案，不需要另外架資料庫。要上規模的時候可以換成 Neo4j、Qdrant、PostgreSQL。
第一次怎麼跑

cognee 的核心是四個動作：記住、回想、忘記、改善。

最小可跑範例 · 存成 test_cognee.py
import cognee
import asyncio

async def main():
    # 第一步：把資料丟進去
    await cognee.add("這個專案用 Next.js 14 App Router，狀態管理用 Zustand，不用 Redux。")

    # 第二步：建立知識圖譜
    await cognee.cognify()

    # 第三步：查詢
    results = await cognee.search("這個專案的狀態管理用什麼")

    for result in results:
        print(result)

if __name__ == '__main__':
    asyncio.run(main())
也可以直接用 CLI，不寫程式
cognee-cli add "你要記住的內容"
cognee-cli cognify
cognee-cli search "你的問題"
接上 Claude Code（對內容創作者最實用的部分）

cognee 有官方的 Claude Code 整合，會掛上生命週期 hook，在 session 開始、工具呼叫後、送出提示前、壓縮上下文前、session 結束時自動記憶跟回想，不需要你手動下指令。

一個重要的預設行為：cognee 會依照不同的 MCP 客戶端自動建立分開的資料集。Claude Code 的記憶存在 claude_code_memory，Cursor 的存在 cursor_vscode_memory，彼此不會互相污染。
希望所有工具共用同一份記憶，關掉隔離
export COGNEE_MCP_AGENT_SCOPED=false
幾個實用細節
  • cognify() 會呼叫 LLM 做實體與關係抽取，這一步是有 token 成本的。丟一整個資料夾進去之前先估算一下
  • 記憶會隨著使用變準。當 agent 對某個回答給出評價，那個回饋會更新圖譜裡的邊權重
  • 支援自訂 ontology。如果你的領域有固定的概念結構（例如「選題 → 腳本 → 素材 → 成品」），可以定義成 schema 讓抽取更準
  • 依賴很重。40 多個核心套件，第一次安裝會跑一陣子，建議開獨立的虛擬環境
⚠️ 真實成本：自架版本本身免費開源，實際成本來自兩個地方。第一，cognify() 的 LLM 呼叫——這個可以用本機模型（Ollama）跑掉，完全免費，代價是抽取品質會差一些。第二，雲端託管版本的計價方式在官方定價頁。
什麼情況不要用
  • 你的專案很小、上下文塞得進單一 session。那多這一層是過度工程
  • 你不想處理 Python 環境問題。這是五個工具裡安裝最麻煩的一個
  • 你需要記憶內容完全可預測。知識圖譜的抽取結果會隨模型而變，不是確定性的
05agency-agents · 一整間 AI 公司的專家角色完全免費
它解決什麼問題：你請 Claude「寫一個 React 元件」，它會寫。但它是用一個通才的視角在寫，不會主動幫你檢查無障礙、不會提醒你 Core Web Vitals、不會質疑你的元件拆分方式。

agency-agents 是一批寫好的專家角色定義，每一個都是一份 Markdown，包含身分設定、工作流程、可交付成果、成功指標、溝通風格。目前超過 230 個角色，橫跨二十多個部門。對做內容的人來說行銷部門特別有用。

⚠️ 為什麼強烈建議「不要全裝」（這是我踩過的坑）：230 多個角色全部倒進 ~/.claude/agents/，每次啟動 Claude Code 都要載入全部的角色描述。結果是啟動變慢、上下文被佔掉一大塊、而且 Claude 在挑選角色時會猶豫，因為選項太多太相似。

實際上你用得到的大概五到十個。先挑一兩個部門，用一個月，看哪些真的有在叫，再決定要不要擴充。

另外有一個已知限制：某些工具的執行環境對角色數量有上限，超過會靜默丟棄後面的。安裝腳本在你的選擇會超過限制時會跳警告。

COMBO 01
內容產出流水線
agency-agents＋cognee

把 cognee 掛上 Claude Code，讓它記住你的品牌調性、禁用句型、過往選題。再裝 agency-agents 的行銷部門角色。結果是：你叫 Instagram Curator 幫你想選題時，它同時知道你的品牌規範跟你上個月發過什麼，不會重複也不會走鐘。

COMBO 02
長任務不中斷
OmniRoute＋agency-agents

跑多角色協作的長任務時，最怕的是中途撞額度。OmniRoute 掛在前面，額度滿了自動換供應商，整條流程不會斷在一半。

COMBO 03
語音轉內容
voicebox＋cognee

用 voicebox 的全域聽寫，把你的口播、會議、隨手想法都轉成文字。轉出來的逐字稿餵給 cognee 建成知識圖譜。一個月之後，你等於有一份自己講過的所有話的可查詢資料庫。寫貼文的時候問它「我之前對這個主題講過什麼」，答案就出來了。

先知道這四件

開源不等於免費。這五個工具的授權都是免費的，但 scroll-world 要付生成費用、cognee 的知識圖譜建立會消耗 LLM token、OmniRoute 掛上付費 Key 之後就在花錢。免費的只有 voicebox 跟 agency-agents。
星數不是品質指標。這幾個 repo 的星數都不低，但星數反映的是曝光跟話題度。裝之前看 issue 區跟最近的 commit 頻率，比看星數有用。
開源專案會變。這份手冊裡的指令、路徑、依賴，都是撰寫當下對照官方 README 確認過的。如果你照著跑出現錯誤，第一件事是回去看該 repo 的 README，不是懷疑自己。
不要一次全裝。拿到一份工具清單的直覺反應是全部裝起來。但工具的價值來自於你真的在用，不是來自於它裝在你電腦裡。挑一個，用滿一個月，再看下一個。
