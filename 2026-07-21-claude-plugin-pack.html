第 0 章 · 安裝前準備

先把地基
弄清楚

0-1 環境檢查

打開終端機（macOS 用「終端機 Terminal」，Windows 用「PowerShell」），貼上這兩行：

檢查版本
node -v
claude --version
  • Node.js 需要 18.0.0 以上。沒裝或太舊，去 nodejs.org 下載安裝完重開終端機。
  • Claude Code 要是支援 plugin 的版本。建議先更新到最新版再往下走。
Windows 出現 npm : The term 'npm' is not recognized，代表 Node.js 沒加進 PATH，重跑一次官方安裝檔，然後把終端機關掉重開。
0-2 三個名詞先搞懂
名詞是什麼怎麼裝
Skill一個 SKILL.md 檔，本質是一段寫好的指令，告訴 Claude 遇到某類任務怎麼做npx skills add
Plugin官方擴充機制，可帶 hooks、slash commands、subagents，能力比 skill 大/plugin marketplace + install
MarketplacePlugin 的來源清單。加了才能從裡面裝 plugin/plugin marketplace add
本包裡：claude-mem、caveman 是 plugin（有 hooks 自動運作）；taste-skill、humanizer、marketingskills 主要是 skill 集合。npx skills 是 vercel-labs 出的跨 agent 安裝 CLI，五個裡有四個都支援。
0-3 建議安裝順序
  • 主要在寫程式：claude-mem → caveman → taste-skill → humanizer → marketingskills
  • 主要在做內容／自媒體：humanizer → claude-mem → marketingskills → taste-skill → caveman
一次只裝一個，裝完重開 Claude Code，確認有動再裝下一個。五個一起灌，出問題你會找不到是誰的鍋。
0-4 一個安裝陷阱（很多人踩）
⚠️ 如果你「叫 Claude Code 幫你安裝」（在 agent session 裡跑 npx skills add），CLI 偵測不到互動環境，可能只裝到通用的 .agents/skills/ 目錄，而 Claude Code 不讀那個目錄。裝完看起來成功，實際沒生效。
解法：明確指定 agent
npx skills add <作者>/<專案> -a claude-code
建議做法：自己開一個新的終端機視窗跑安裝指令，不要在 Claude Code 對話裡面裝。

01claude-mem · 讓 Claude 記得住上一次
GitHub thedotmack/claude-mem｜授權 Apache 2.0｜作者 Alex Newman

Claude Code 每開一個新 session，前面講過的東西全部歸零——專案架構、命名習慣、上次踩的坑，每次都要重講。claude-mem 用 lifecycle hooks 在你工作時自動側錄，把過程用 AI 壓縮成語意摘要存進本機 SQLite，下次開新 session 時把相關部分自動注入回去。

安裝
方法 A（推薦，一行搞定）
npx claude-mem install
方法 B（從 plugin marketplace）
/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem

裝完 重啟 Claude Code。

⚠️ 這個一定要注意：官方明講 npm install -g claude-mem 只會裝 SDK／library，不會註冊 plugin hooks，也不會啟動 worker service——用了等於沒裝。一律用 npx claude-mem install 或 /plugin 指令。
驗證有沒有裝成功
重啟後在瀏覽器打開
http://localhost:37777

看得到即時記憶串流介面，就代表 worker service 有跑起來。這個網頁 UI 可以直接看它記了什麼、切換設定、切 stable／beta 版。

怎麼用

基本上不用管它——自動側錄、自動注入。要查歷史直接問 Claude「我們上禮拜怎麼處理那個登入的 bug？」，它會自己跑 search → timeline → get_observations 三層流程（先撈精簡索引、再撈細節），官方說約可省 10 倍 token。

語言模式與隱私
~/.claude-mem/settings.json（改完重啟）
{
  "CLAUDE_MEM_MODE": "code--zh"
}
給台灣使用者：官方目前的中文模式是簡體（code--zh），沒有繁體。觀察摘要是給 Claude 讀的、不是給你讀，用預設英文完全不影響使用。不想被記的內容用 <private>…</private> 包起來。資料全存你自己電腦的 SQLite，不是雲端。
⚠️ 什麼時候該關掉：處理極機密專案、連本機摘要都不想留時；專案上下文每次都完全不同、沒有延續性時（記憶反而變雜訊）。
官方：github.com/thedotmack/claude-mem
02caveman · 讓 Claude 少講廢話
GitHub JuliusBrussee/caveman｜授權 MIT｜作者 Julius Brussee

Claude 回你一段話，前兩句是「當然！我很樂意幫你」，中間三句在解釋要做什麼，真正答案只有一句。caveman 直接叫 agent 砍掉贅字、用碎句回答，但程式碼、指令、錯誤訊息一個字元都不動。

安裝
方法 A（推薦，自動偵測所有 agent · macOS/Linux/WSL）
curl -fsSL https://raw.githubusercontent.com/JuliusBrussee/caveman/main/install.sh | bash
Windows · PowerShell 5.1+
irm https://raw.githubusercontent.com/JuliusBrussee/caveman/main/install.ps1 | iex
方法 B（只裝 Claude Code）
claude plugin marketplace add JuliusBrussee/caveman && claude plugin install caveman@caveman

約 30 秒，需要 Node ≥ 18，沒裝的 agent 會自動跳過，重複執行安全。在 Claude Code、Codex、Gemini 上，安裝完從第一則訊息就是開著的。

開關與壓縮等級
等級效果
lite輕度，句子還完整
full（預設）碎句化，資訊密度高
ultra極限壓縮
wenyan文言文模式，每 token 塞的意思最多
開關與常用指令
/caveman              # 開啟（說 normal mode 關閉）
/caveman ultra        # 切換壓縮等級
/caveman-commit       # 產 Conventional Commit 訊息
/caveman-review       # 一行式 PR 註解
/caveman-stats        # 算實際省下的 token 與美金（--share 產社群版）
/caveman-compress <檔案> # 把 CLAUDE.md 這類記憶檔改寫成壓縮版
語言不會被翻譯。你用中文問，它就用中文咕嚕，壓縮的是「風格」不是語言（wenyan 是刻意的例外）。/caveman-compress 把每次都載入的記憶檔重寫成精簡版，之後每個 session 都少載——官方測 5 個記憶檔平均縮減 46%。
⚠️ 誠實的數字：官方 benchmark 10 個 prompt 平均輸出 token 減 65%（範圍 22–87%），但作者自己標注：只砍輸出 token，skill 本身每回合多吃約 1–1.5k 輸入 token，整個 session 實際節省比 65% 小很多，在本來就簡潔的任務上甚至可能倒賠。真正的收穫是閱讀速度與效率，省錢是附加的。外面拿「省 65%」當標題在賣，作者自己都沒這樣講。
⚠️ 什麼時候該關掉：要寫給人看的長文／貼文／email 時；做需要來回推敲的策略討論時；任務本來輸出就很短時。跟 humanizer 一起用要注意順序——要產出給人看的文案時，先說 normal mode 關掉 caveman，再叫 humanizer，兩個都開會互相打架。
官方：github.com/JuliusBrussee/caveman｜無 telemetry、無帳號、零網路請求
03humanizer · 把 AI 味洗掉
GitHub blader/humanizer｜授權 MIT

AI 寫的文字有一股味道。「在當今快速演變的環境中」、「這不僅僅是 X，更是 Y」、三點式排比、結尾一定要昇華。讀者說不上來哪裡怪，但知道這不是人寫的。humanizer 把這件事拆成 33 個具名的模式，一條一條抓出來改掉，依據是 Wikipedia 的「Signs of AI writing」指南。

安裝
方法 A（跨 agent CLI）
npx skills add blader/humanizer
方法 B（Claude Code plugin，呼叫方式 /humanizer:humanizer）
/plugin marketplace add blader/humanizer
/plugin install humanizer@humanizer
進階：Voice Calibration（這才是重點）

直接用會得到「乾淨但沒有人味」的文字。要它像你寫的，先餵自己的樣本：

先餵樣本再改寫
/humanizer
Here's a sample of my writing for voice matching:
[貼 2–3 段你自己寫的東西]

Now humanize this text:
[貼要處理的 AI 文字]
它會先分析你的句子節奏、用字習慣、個人癖好，再套用到改寫。這一步做跟不做，差距非常大——建議把自己最滿意的 3 段文字存成一個檔，每次直接貼。
為什麼把它放進這份清單
它抓的模式裡有「負向排比（這不只是 X，這是 Y）、格言公式、假坦白式開場」——跟我自己文案裡的禁用句型幾乎一模一樣。它還有一個「明顯是 AI 寫的」最終稽核回合，會再掃一次殘留。
⚠️ 什麼時候該關掉：寫技術文件、API 說明、規格書（這種文體本來就該工整）；你的品牌調性本來就偏正式。
官方：github.com/blader/humanizer
04taste-skill · 介面不像 AI 做的
GitHub Leonxlnx/taste-skill｜官網 tasteskill.dev｜授權 MIT

叫 AI 做一個 landing page，出來的東西技術上沒問題，但一看就是套版：置中大標、三個並排卡片、間距全一樣、零動態。taste-skill 是一組可攜的 Agent Skills，專門處理版面、字體、動態、間距——不綁框架（React／Vue／Svelte 都能用），因為它規範的是設計意圖，不是某個 API。

安裝
一次裝全部（掃 skills/ 資料夾）
npx skills add https://github.com/Leonxlnx/taste-skill
只裝單一 skill（用 install name，不是資料夾名）
npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"
⚠️ v1／v2 版本問題：預設的 design-taste-frontend 目前是 v2（experimental），是 v1 的大幅重寫。裝過 v1 的重跑安裝就會升級。若你依賴 v1、v2 弄壞你的流程，可明確指定 --skill "design-taste-frontend-v1"。

05marketingskills · 一整個行銷團隊
GitHub coreyhaines31/marketingskills｜官網 marketing-skills.com｜授權 MIT｜作者 Corey Haines

將近 50 個行銷技能包，涵蓋 CRO、文案、SEO、廣告、分析、成長工程。裝完之後你講「幫我優化這個 landing page 的轉換率」，Claude 會自動抓對應 skill，套用該領域的框架去做。設計給的是技術型行銷人和獨立創業者——自己一個人要扛完所有行銷的那種角色。

安裝
方法 A（推薦）
# 全部裝
npx skills add coreyhaines31/marketingskills
# 只裝指定的
npx skills add coreyhaines31/marketingskills --skill cro copywriting
# 先看有哪些
npx skills add coreyhaines31/marketingskills --list
⚠️ 這裡最容易裝錯：在 agent session 裡跑（叫 Claude Code 幫你裝），CLI 用非互動模式，可能只裝到通用的 .agents/skills/ 目錄，而 Claude Code 不讀那個目錄。明確指定 agent：
明確指定 agent
npx skills add coreyhaines31/marketingskills -a claude-code
🔑 裝完第一件事：跑 product-marketing
product-marketing 是整套的地基，其他每一個 skill 動手前都會先讀它，用來理解你的產品、受眾、定位。跑一次 /product-marketing，跟著問題回答，它會產出 context 存在 .agents/product-marketing.md。跳過這步，你會得到一堆泛泛而談的通用建議。
給自媒體經營者的三個切入點
  • lead-magnets — 規劃、評估、優化引流磁鐵（你現在看的這份文件就是一個 lead magnet）
  • ai-seo — 針對 AI 搜尋做優化，讓 LLM 回答時引用到你（這塊現在還沒什麼人在做）
  • marketing-loops — 設定可重複、自己跑的行銷流程，讓 AI agent 定期執行
用法直接講人話：「幫我優化這個 landing page 的轉換率」→ 自動用 cro；「幫我的 SaaS 寫首頁文案」→ 自動用 copywriting；也可直接叫 /cro、/emails、/seo-audit。近 50 個 skill 涵蓋轉換優化、內容文案、SEO、付費投放、數據測試、留存、成長工程、策略變現。
官方：github.com/coreyhaines31/marketingskills｜marketing-skills.com

第 7 章 · 疑難排解與移除

卡住的時候
回來翻這裡

裝完沒反應，Claude 完全沒變
最常見是裝到 Claude Code 讀不到的目錄。重跑安裝並加 -a claude-code，然後完全關掉 Claude Code 再重開（不是開新對話，是關掉整個程式）。
claude-mem 的 localhost:37777 打不開
Worker service 沒起來。先確認 Node ≥ 18，再重跑 npx claude-mem install。之前若用過 npm install -g claude-mem，那只裝了 SDK，要用正確指令重裝。
怎麼知道 skill 到底有沒有被觸發
直接問 Claude：「你剛剛用了哪個 skill？」它會告訴你。
Windows 出現 npm is not recognized
Node.js 沒進 PATH。到 nodejs.org 重裝，裝完重開終端機。
移除 · 更新
移除 caveman
npx -y github:JuliusBrussee/caveman -- --uninstall
更新（skills CLI 通用）
npx skills update <skill 名稱>
其他 plugin 在 Claude Code 裡用 /plugin 指令管理；skill 類直接刪掉對應目錄的資料夾即可。

工具裝完了，接下來換我陪你把它接成系統
