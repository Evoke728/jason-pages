02匯入你的記憶 · 三分鐘搬完幾個月的累積
為什麼：如果你之前已經在用 ChatGPT 或 Gemini，那些工具花了幾個月才學會你的語氣、你的專案、你的偏好。換一個工具就要重新教一次，這是換工具最大的成本。Claude 提供了一個官方的匯入工具，把這件事壓縮到三分鐘。

第三步要刪掉的常見東西：已經不做的舊專案、換過的居住地或工作、早就改掉的偏好設定、不想讓 Claude 知道的私人細節。
幾個要知道的事
  • 支援來源：ChatGPT、Gemini、Grok 都可以
  • 生效時間：官方說明指出完整套用到所有對話最多需要 24 小時，實際上通常更快
  • 偏重工作脈絡：Claude 的記憶設計以工作相關內容為主，跟工作無關的個人細節可能不會被保留
  • 可以多次匯入：每次匯入是疊加，不會覆蓋既有記憶，可以分批把 ChatGPT、Gemini 的內容都搬過來
  • 這是實驗性功能：官方明確標注仍在開發中，匯入結果不一定每次都完整

03選對模型 · 預設 Sonnet，不夠才往上
為什麼：模型選錯有兩種後果：用太弱的處理複雜任務，答案品質不夠；用太強的處理簡單任務，額度燒得比誰都快。這兩件事都會讓你覺得「這工具沒有想像中好用」。
模型定位什麼時候用額度消耗
Haiku最輕、最快分類、抓資料、改格式、簡單問答最低
Sonnet日常主力大部分寫作、分析、一般編碼中等
Opus難題與長任務深度分析、複雜推理、長文件拆解、agent 流程高
Fable最高能力最長、最複雜、最重要的專案最高
Opus 需要付費方案才能使用。Fable 是 Anthropic 目前最強的模型，同樣在付費方案的 model picker 裡可以選，它會花更多時間思考再回答，回應比較慢，額度消耗也最大。
實際的選法
預設用 Sonnet。這是最省事也最不會出錯的做法
遇到答案不夠深或明顯出錯的時候，升到 Opus 重跑一次
Opus 也處理不了，而且這個任務又長又重要，那才是 Fable 的場合
任務單純又重複（例如把一百筆資料改格式），降到 Haiku
一個更好用的旋鈕：Effort
很多時候調 Effort 比換模型更有效，也更省。先試著在 Sonnet 上把 Effort 調高，再決定要不要換 Opus。
官方模型選擇說明
04建立你的 Projects · 按領域分，不要按時間分
為什麼：一般對話每次都從零開始。Projects 讓你把指令和參考資料存一次，之後每個在這個 Project 裡開的新對話，都已經讀過那些東西。你的品牌語氣、禁用詞、目標受眾、過去表現好的貼文，存進去一次，之後每次寫文案都不用再貼一遍。
路徑左側邊欄 Projects → Create Project，或直接到 claude.ai/projects 免費方案可以建立 5 個 Project
Project 的兩個核心元件
  • Custom instructions（自訂指令）：告訴 Claude 在這個 Project 裡該怎麼行動。這是決定 Project 好不好用的關鍵
  • Project knowledge（知識庫）：上傳參考檔案。.md 和 .txt 格式的辨識效果最好，PDF 也支援但準確度較低。付費方案在檔案量變大時會自動啟用 RAG 檢索
怎麼分 Project
Project 名稱放什麼
內容製作品牌語氣、禁用詞清單、過去高表現貼文、受眾輪廓
客戶 A該客戶的品牌指南、過往交付物、溝通紀錄

⚠️ 不要建一個叫「雜項」的 Project 然後把 47 個檔案丟進去。主題不一致的知識庫會讓檢索品質下降。

06接上你的工具 · 但不要全部開著
為什麼：沒有接工具的 Claude 只能給你建議，你還要自己去複製貼上。接上之後它可以直接讀你的檔案、寫進你的資料庫。對做內容的人最有感的三個：Google Drive（讀素材）、Notion（存產出）、Gmail（處理往來）。
新版介面Customize → Connectors 舊版介面Settings → Connectors 或者對話框裡點 + 按鈕也可以開啟連接器選單

走 OAuth 流程，用你原本的帳號登入
審核它要求的權限，同意
用的是 OAuth 授權，你不會把密碼交給 Anthropic。Claude 只能存取你主動要求它取用的資料，而且僅限你在該工具裡本來就有權限看到的內容。底層是 MCP（Model Context Protocol）這個開放標準，任何支援 MCP 的服務理論上都能接進來，包含你自己架的。
⚠️ 一個很多人踩的坑：開著的連接器會吃 token。每一個啟用的連接器都會把它的工具說明塞進對話的脈絡裡，佔用空間。開十個連接器等於每次對話都先浪費一段額度。

做法：在對話框點 +，只留下這次會用到的，其他關掉。寫客戶信的時候開 Gmail、Google Drive，關掉 Notion、Canva；整理筆記的時候開 Notion，關掉其他。

Project instructions 只在那個專案
Skill 是全域的

Skill 是一個資料夾，裡面放著教 Claude 完成某個特定任務的指令。你寫一次，之後 Claude 在遇到相關任務時會自動載入。Skills 在 Free、Pro、Max、Team、Enterprise 各方案都可以使用。

⚠️ 前置條件：先開啟 Code execution。Skills 需要程式碼執行環境才能運作。

Free / Pro / Max：到 Settings → Capabilities，確認「Code execution and file creation」是開啟的。
Team / Enterprise：需要 Owner 在 Organization settings → Skills 裡把「Code execution and file creation」和「Skills」都打開。

沒開這個，Skills 區塊會是灰色的或根本不顯示。
建立路徑Customize → Skills（claude.ai/customize/skills）→ 點「+」→「+ Create skill」 最省事選 Create with Claude，用對話的方式描述你的流程

# IG 輪播貼文文案產出

## 流程

1. 判斷主題屬於哪種內容類型（教學 / 比較 / 觀點 / 故事）
2. 規劃張數，建議 7 到 8 張
3. 逐張產出：標題（大字）+ 正文（要點）
4. 最後一張是 CTA

## 語氣規範

- 直接、清楚、可以直接套用
- 專有名詞保留英文，不翻譯
- 繁體中文，台灣用字

## 禁用句型

- 不用「不是…而是…」這類對比轉折
- 不用勵志收尾
- 不用假設共鳴的問句開場
- 不用「值得注意的是」「真正的 X 是」

## 輸出格式

每張輸出：

【第 N 張】
標題：
正文：

最後附上一段 IG 貼文說明文案，100 到 180 字。
兩個規格限制：name 最多 64 字元、description 最多 200 字元。
description 決定觸發率

這是最多人做錯的地方。Claude 靠 description 判斷什麼時候要載入這個 Skill。

✕ 觸發率低description: 幫忙處理內容相關的事情
✓ 觸發率高description: 產出 IG 輪播貼文的完整文案結構，包含每張標題、正文與 CTA。當使用者說「幫我寫輪播貼文」「幫我做 IG 文案」「這個主題做成輪播」時觸發。
差別在於：具體的任務描述 ＋ 明確的觸發詞。另外，Claude 對簡短的請求傾向自己處理而不載入 Skill，測試的時候要用有一定複雜度的 prompt，不要只打一句「寫個文案」。
上傳與測試
把 Skill 資料夾壓縮成 ZIP（ZIP 的根目錄要包含資料夾本身，不是只有裡面的檔案）
Customize → Skills →「+」→「+ Create skill」→「Upload a skill」
上傳後會出現在清單裡，可以隨時開關
用三到五個不同說法的 prompt 測，看 Claude 的思考過程裡有沒有出現「Using [skill name]」
該從哪個 Skill 開始

第三部分 · 跨 AI 記憶搬家

每個平台
匯出方式不同

從 ChatGPT 搬過來

方法 A · 記憶摘要（快，三分鐘）：用上面第二步那段匯出 prompt。

建議先去清理再匯出。ChatGPT 的記憶是累積的，裡面常常有過期資訊。手動檢查路徑：ChatGPT Settings → Personalization → Memory → Manage，刪掉過期的，再回去跑匯出 prompt。

方法 B · 完整對話紀錄（慢，但完整）：ChatGPT Settings → Data Controls → Export data。OpenAI 會寄一個下載連結給你。這份檔案 Claude 目前沒有直接匯入的功能，但你可以從裡面挑重要的對話手動整理成摘要再匯入。

從 Gemini 搬過來

在 Gemini 開新對話，貼同一段匯出 prompt。要知道的事：Gemini 的記憶模型跟 ChatGPT 不同，它儲存的明確使用者資料較少，比較多是對話脈絡。所以匯出的內容通常比 ChatGPT 少，這是正常的。

從 Grok 搬過來

同樣的 prompt，同樣的流程。Claude 的匯入工具明確支援 Grok 作為來源。

第四部分 · 模型選擇

不夠用才往上，太浪費就往下。

你在做什麼建議模型理由
改格式、抓資料、分類Haiku任務結構清楚，不需要推理深度
寫貼文、寫腳本Sonnet日常主力，品質和速度平衡
拆解長文件、深度分析Opus需要在長脈絡裡維持一致性
多步驟自動化流程Opus中間一步錯會連鎖影響後面
最長、最複雜、最重要的專案Fable能力上限最高，也最慢最耗額度
大量重複的機械任務Haiku一百次 Haiku 比十次 Opus 划算
一個實際的省額度策略
設計用強的，執行用弱的。第一次設計流程用 Opus 把邏輯想清楚，之後每週執行用 Sonnet 或 Haiku。更進一步：把設計好的流程做成 Skill，之後連 prompt 都不用重貼。
Effort：比換模型更好用的旋鈕
  • 遇到答案不夠深 → 先在同一個模型把 Effort 調高，再考慮換模型
  • 只是要快速確認一件事 → Effort 調低，省時間也省額度
  • 最難的問題 → Effort 拉到最高，接受它會思考比較久
⚠️ 很多人直接從 Sonnet 跳到 Opus，其實把 Sonnet 的 Effort 調高就解決了，而且省很多額度。額度消耗由低到高：Haiku < Sonnet < Opus < Fable。
