Part 0 · AI 網站長得都一樣

原因在這裡
這是統計行為，不是能力問題

大型語言模型在生成前端的時候，會朝訓練資料裡最常見的模式收斂。網路上公開的 landing page 有幾百萬個，其中絕大多數是 2020 到 2024 年之間的 SaaS 模板。模型看到的「網站」平均長相就是那個樣子。你不給它額外的方向，它就給你平均值。

換模型救不了
換一個更新、更強的模型，得到的結果通常是「同樣的長相，但程式碼更乾淨」。平均值被拉高了，長相沒有改變。
AI Slop 的九個明顯特徵

以下這些出現在你的頁面上，就代表模型在照著平均值做事：

1藍紫或紫粉的漸層標題文字
2全站只有一種字體，通常是 Inter 或系統預設
3卡片裡面包卡片，圓角一律 12px
4每個標題上面都有一個圓角方形的 icon 磚
5三欄等寬的功能區塊，每欄一個 icon 加兩行字
6彩色背景上放灰色小字
7玻璃擬態的半透明卡片
8Hero 區塊一定是「大標題 + 副標 + 兩顆按鈕」置中
9深色模式配霓虹強調色
解法的邏輯

模型缺的是詞彙。設計師在描述一個頁面的時候，腦中有一整套詞：視覺層級、留白節奏、字體對比、裝飾克制、動態的必要性。這些詞不在你的 prompt 裡，模型就只能用它自己的預設值。

建立品味庫：把你喜歡的東西變成可以被描述的詞
武裝 Claude：裝上讓它擁有設計詞彙的 Skills
一次生多版：用比較取代猜測
Part 1 · 建立品味庫

投報率最高的一步
而且只需要做一次

你在下 prompt 的時候，如果只能寫「做得好看一點」「再高級一點」，那你其實沒有給模型任何資訊。「好看」對模型來說就是平均值。品味庫的作用是把「我喜歡這個」轉換成「這個是 print-tech 風格，特徵是淺鼠尾草底色、等寬字座標標籤、地形線插畫」。後者可以直接貼進 prompt，前者不行。

蒐集來源與搜尋方式
  • Dribbble：搜尋 web design、landing page、editorial website，排序改成 Popular。看排版與配色，不是那些永遠不會實作的動畫概念稿。
  • Pinterest：搜尋 hero section design、web layout inspiration。價值在於你會看到自己絕對想不到的版面結構。
  • X / Twitter：追蹤前端設計師，他們會直接貼正在做的 UI，包含靜態截圖看不到的互動細節。
  • Awwwards、Godly、Land-book：三個專門收錄網站的目錄，可以直接看到實際運作的網站。
  • 日常截圖（最重要的一項）：任何時候滑手機或用電腦，只要有畫面讓你停下來，立刻截圖。不用當下判斷為什麼喜歡，先存下來。
存連結，不只存圖

靜態截圖會漏掉三件事：滾動時的動態、互動狀態、真實的字體渲染。養成習慣：喜歡的網站，截圖同時把 URL 存進同一筆記錄。之後直接把 URL 丟給 Claude，讓它自己去看。

按設計家族分類，不要按專案分類

大部分人的第一直覺是按產業分：SaaS、電商、作品集、部落格。這個分法沒有用，因為產業跟長相沒有必然關係。

家族名稱特徵
Print-Tech印刷感、技術標記、座標與時間戳、等寬字
Dither Mono單色、抖動網點、低解析度質感
Vast Quiet大量留白、極小字、單一巨大影像
Classical Remix古典繪畫或雕塑素材、襯線字、當代排版
Illustrated Storybook手繪插畫、飽和色、圓潤字體
Data-as-Texture把數據視覺化當成背景紋理
Editorial Serif雜誌感、大襯線標題、多欄文字
Brutalist Grid粗框線、高對比、刻意的不對稱
不需要一開始就有八個家族。從三個開始，每次存新東西的時候問自己「這個屬於現有的哪一個，還是要開新的」。
幫每個風格命名

命名是這一步的核心。有名字的東西才能被叫出來。命名規則：兩個詞，一個講質感，一個講技術或載體。範例：Print-Tech、Dither Mono、Halftone Sail、Vast Quiet、Marble Cinematic。命名之後，幫每個家族寫三到五個特徵詞——這些詞就是你之後 prompt 裡的原料。

Prompt · 讓 Claude 幫你分析截圖
截圖分析 Prompt
我要建立一個網頁設計的品味庫。以下是我蒐集的截圖。
請你針對每一張，輸出以下六個欄位：

1. 設計家族：用兩個英文詞命名這個風格（例如 Print-Tech、Vast Quiet）。
   如果多張屬於同一家族，用同一個名字。
2. 視覺詞彙：5 到 8 個具體的描述詞。
   要描述可觀察的東西（配色、字體種類、間距密度、裝飾元素、影像處理方式），
   不要用「現代」「乾淨」「專業」這類無法執行的形容詞。
3. 字體策略：標題字體類型、內文字體類型、兩者的對比關係、
   是否有等寬字或特殊字重的使用。
4. 色彩策略：底色、主文字色、強調色，各給一個近似的 hex 值。
   說明強調色被用在哪些地方。
5. 版面骨架：Hero 區塊的結構、內容區塊的欄位數、
   留白的比例、是否有明顯的網格系統。
6. 可複製的關鍵字串：把上述整理成一段 30 到 60 字的英文描述，
   格式為可以直接貼進設計 prompt 的一句話。

輸出格式：每張截圖一個 Markdown 區塊，用二級標題分隔。
最後補一張總表，列出所有出現的設計家族與各自的數量。
Prompt · 讓 Claude 幫你做品味庫 App

截圖散在資料夾裡很難用。讓 Claude 幫你做一個本地端的資料庫介面。

品味庫 App Prompt
幫我做一個本地端執行的網頁應用，用途是管理我的網頁設計品味庫。

技術規格：
- 單一 HTML 檔案，內嵌 CSS 與 JavaScript，不依賴後端
- 資料存在同目錄的 data.json，我會手動編輯或用介面新增
- 圖片檔放在 ./screenshots/ 資料夾，用檔名引用

每一筆資料包含以下欄位：
- id：流水號
- name：這個網站或風格的名稱
- family：設計家族（用來分組）
- screenshot：圖片檔名
- url：原始網址（可留空）
- vocabulary：陣列，5 到 8 個視覺詞彙
- typography：字體策略的文字說明
- colors：陣列，每個元素是 { hex, role }
- keywords：陣列，可直接丟進 prompt 的關鍵字
- image_prompt：一段用來生成 hero 背景圖的英文 prompt
- brief：一段 60 到 100 字的英文，描述如果要用這個風格做一個網站，
  整體方向該怎麼定

介面需求：
- 主畫面是卡片瀑布流，每張卡片顯示截圖縮圖、名稱、家族標籤
- 左側是設計家族的篩選器，點擊後只顯示該家族
- 頂部有搜尋框，可以搜尋 name、vocabulary、keywords
- 點擊卡片展開詳細頁，顯示所有欄位
- 詳細頁的 keywords、image_prompt、brief 三個欄位各有一個複製按鈕
- 有一個「組合 prompt」模式：可以勾選多筆資料，
  系統把它們的 keywords 合併，輸出一段可複製的文字

設計要求：
- 介面本身要有設計感，不要用 Inter 或系統預設字體
- 不要藍紫漸層，不要卡片裡包卡片
- 底色用暖色系的淺色，強調色只用一種

先做出可以跑的版本，我看過之後再調整。
每一筆該記錄什麼
欄位作用
Design family分組用。同家族的資料可以互相補強
Vocabulary這個風格是由哪些詞組成的
Keywords縮短版，直接丟進 prompt
Image prompt給 hero 背景圖生成用
Brief整個網站的方向設定，最重要的一欄
Brief 這一欄是很多人會省略的，但它決定了輸出的完整度。Keywords 只能影響表面樣式，Brief 會影響版面決策。
Part 2 · 武裝 Claude

Claude Code 原生
沒有設計詞彙

以下這些工具的作用是把詞彙補上去。

01impeccable · 規則與檢查
Paul Bakaus 開發Apache 2.0impeccable.style
它做的事：給 Claude 一整套設計語言，包含 23 個指令、7 份深度參考文件（色彩、字體、動態、空間設計、互動、響應式、UX writing）、一個瀏覽器內的即時編輯模式。
安裝
npx impeccable install
初始化，會產出 PRODUCT.md 與 DESIGN.md
/impeccable init
之後所有指令都會讀這兩個檔案，所以初始化時它問的問題要認真回答。
最常用的三個指令
指令用途什麼時候用
/impeccable audit掃描目前的頁面，找出 slop 模式第一版做完，還沒開始調之前
/impeccable bolder把過於保守的設計往上推東西沒有錯，但看起來很平的時候
/impeccable polish上線前的最後整理準備 deploy 之前
額外的 CLI 偵測器，不需要 AI 就能跑
npx impeccable detect src/
npx impeccable detect https://example.com
這個可以掛進 CI，讓有 slop 的 PR 直接被擋下來。
⚠️ 官網 impeccable.style 上有每個指令的 before / after 對照。第一次用之前先去看一輪，你會比較知道哪個指令對應哪種問題。
02Taste Skill · 風格與強度調整
定位：impeccable 偏向「規則與檢查」，Taste Skill 偏向「風格與強度調整」。它的特色是三個可調的參數，運作方式像等化器。
  • VARIANCE：設計語言的變化幅度
  • MOTION_INTENSITY：動態的深度（低是 hover，高是滾動觸發與磁吸效果）
  • VISUAL_DENSITY：每個視窗裡的資訊量（低是留白型，高是儀表板型）
安裝
npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"
兩套可以同時裝。作者的用法是 Taste Skill 定調性，impeccable 做檢查。
03Higgsfield MCP · 圖像與影片
它做的事：前面兩個處理排版與樣式，這一個處理圖。Hero 圖用免費圖庫的問題是，那些圖大家都在用，一看就知道來源。Higgsfield MCP 讓你在 Claude Code 裡直接生圖跟生影片，不用切換視窗。
模型選擇
  • 靜態圖：GPT Image 2
  • 影片：Seedance（字節跳動的影片模型，Higgsfield 上可用）
裝好後在 Claude Code 裡確認連線
/mcp
看到 higgsfield — connected 就可以用了。
0421st.dev · 元件層級資源庫
它做的事：按鈕、卡片、定價表、導覽列這些東西，站上有現成的 prompt 可以直接複製。用法：找到你要的元件，複製 prompt，貼進 Claude Code，它會照著實作。
價值在哪裡：邊框處理、背景層次、分頁樣式這些細節，你自己下 prompt 的時候通常不會想到要指定，結果就是拿到預設值。
該避開的東西

有一類 Skill 是「單一功能、規則寫死」的。它們的問題是每次輸出都一樣，用第三次的時候你就會發現所有頁面長得像同一個模板。判斷方式：如果一個 Skill 沒有任何可調參數，也不會問你關於專案的問題就直接開始做，那它大概屬於這一類。

方向盤要留在你手上
工具的作用是擴充可能性，不是替你做決定。
CLAUDE.md 的設定建議

在專案根目錄放一個 CLAUDE.md，把不變的規則寫進去，可以省下每次重複交代的時間。這份檔案寫一次，之後每個專案複製過去改參數就好。

CLAUDE.md · 設計規則
# 設計規則

## 永遠
- 每個頁面有一張主導視覺，尺寸大到足以定調
- 影像必須經過處理（半調網點、抖動、顆粒、ASCII、線稿），不用原圖
- 排版走兩極：巨大的展示字或極小的等寬標籤，中間尺寸少用
- 近乎單色的底，加單一暖色強調

## 永不
- 紫色到藍色的漸層
- 光澤感的 3D 立體形狀
- 未經處理的免費圖庫照片
- 所有東西都圓角
- icon 網格式的功能列
- 只用 Inter 或系統字體
- 平均分布的多彩配色

## 字體
- 標題：[你的選擇]
- 內文：[你的選擇]
- 等寬：[你的選擇]

## 色彩
- 底色：#______
- 主文字：#______
- 強調：#______（只用在 ______）

Part 3 · 不要單發，一次生五版

用比較
取代猜測

一次只生一個版本，你得到的是模型當下的第一直覺。你沒有比較對象，所以你只能判斷「這個我喜不喜歡」，無法判斷「有沒有更好的方向」。而且你會陷入一個循環：不喜歡，叫它改，它改了一點，還是不喜歡，再叫它改。每一輪都在原地打轉，因為你們兩個都不知道目標長什麼樣。

收斂的四個階段
5 STYLES同樣的內容，五種設計家族，各做一版——判斷哪個方向對
↓
3 VARIANTS選定風格，內文區塊做三個變體——判斷哪個結構對
↓
1 WINNER定案，把 hero 圖做到位——判斷整體氣氛對不對
↓
TWEAKS字體、色彩、動態的小幅調整——判斷細節有沒有到位
範圍越窄，完成度越高。一開始就鎖死一個方向，你會在錯的方向上做出很完整的東西。
為什麼要在瀏覽器裡比，不在終端機裡比

終端機會藏住你的選擇。Claude 在終端機裡描述五個方向給你聽，你聽起來都差不多，因為文字描述無法傳達視覺差異。正確做法是讓它把五個版本都做出來，放在同一個頁面上，你用眼睛比。

主控 Prompt · 五風格 bake-off

這是整份文件最重要的一段。複製之後把方括號的部分換成你的內容。

五風格 Bake-off 主控 Prompt
幫我做一個 landing page，主題是 [產品名稱]，[一句話說明這是什麼]。
轉換目標：[例如：預約 Demo]。
每一版的主要 CTA 文字都是「[CTA 文字]」，
必須出現在 hero 區塊，並在頁面結尾重複一次。

## 意圖
這個產品要傳達的感覺是：[例如：小團隊的不公平優勢、
經過設計的智慧、冷靜而有自信，不要吵鬧的 SaaS 語氣]。
一個創辦人看到這個頁面，應該在三秒內想「這群人是真的懂這件事」。

## 護欄
永遠：
- 一張主導視覺定調整個頁面
- 影像經過處理（半調網點、抖動、顆粒、ASCII、線稿），不用原圖
- 技術性的邊註（座標、編號、尺規刻度、時間戳）
- 排版走兩極：巨大展示字或極小等寬標籤，中間尺寸少用
- 近乎單色的底，加單一暖色強調

永不：
- 紫色到藍色的漸層
- 光澤感的 3D 形狀
- 未經處理的免費圖庫照片
- 所有東西都圓角的親切感
- icon 網格式的功能列
- 只用 Inter 或系統字體
- 平均分布的多彩配色

## 執行方式
做五個版本，各自放在自己的資料夾（v1/ 到 v5/），
一個資料夾對應下面一個方向。
五個版本共用同一份意圖與護欄。
不要混合方向，每一版完整承諾它自己的美學。

  • Aesthetic：詞彙越具體越好，但控制在 8 個以內。超過的話模型會開始取捨，而且你無法預測它捨掉哪個。

Part 5 · 迭代順序

順序錯了
你會一直改被推翻的東西

第一版出來之後，改的順序有講究。

1Hero

先把 hero 定下來。這一塊決定了整個頁面的氣氛，後面所有東西都是配合它。Higgsfield 生四張，選一張，調整色調讓它跟頁面配色一致。

2轉場

Hero 跟內文之間不要硬切。加一個過渡：漸層遮罩、重疊的區塊邊界、或者讓 hero 圖延伸進第一個內容區塊。

3動態

頁面載入要有重量感。元素進場的時候，加一點延遲跟緩動，讓它感覺是「被放置」而不是「被貼上」。克制是關鍵。選一個代表性的動態時刻，把它做好，其他地方保持安靜。所有東西都在動，等於沒有東西在動。

4Tweaks Bar · 很多人不知道可以做
Tweaks Bar Prompt
幫我做一個浮動的調整面板，固定在頁面右側，可以收合。
面板包含：
- 標題字體：下拉選單，列出 8 個候選字體，即時切換
- 內文字體：同上
- H1 字級：滑桿，範圍 32px 到 96px
- H1 字距：滑桿，範圍 -0.05em 到 0.05em
- H1 字重：滑桿
- 內文字級：滑桿，範圍 14px 到 20px
- 區塊間距：滑桿，範圍 40px 到 200px
- 強調色：色票選擇器
- 底色：色票選擇器

所有調整即時反映在頁面上。
面板底部有一個「輸出目前設定」按鈕，
點擊後把當前所有數值輸出成 CSS 變數的區塊，可以複製。

這個面板只在開發時使用，用一個 URL 參數 ?tweaks=1 控制顯示。
做出這個面板之後，你就不用再叫 Claude「字再大一點」「間距再開一點」。自己拉滑桿，拉到滿意，輸出設定，貼回去。

每次覺得哪裡不對，回品味庫找一個對應的參考丟給它。

不要說的話
✕ 沒有可執行的資訊「再高級一點」「做得更有設計感」「感覺還是有點 AI」「再現代一點」

附錄 C · 常見錯誤

六個
最常見的坑

跳過品味庫，直接開始生
結果是你在下 prompt 的時候只能寫抽象形容詞，模型回到平均值。品味庫這一步做兩個小時，之後每個專案省兩天。
一開始就要求「完美的一版」
模型在第一次生成的時候不知道你要什麼。橫向出五版，你花的時間差不多，但你會知道自己要哪個。
先做圖，再做版面
Hero 圖先定案的話，你會為了遷就那張圖去改版面。順序應該是版面先定，圖片槽位先預留，最後才放圖。
在終端機裡調視覺
視覺的東西要用看的。做一個 tweaks bar，拉滑桿比打字快十倍，而且你會看到中間值。
裝了 Skill 就不管了
Skill 提供的是詞彙與檢查，方向還是你決定的。裝了 impeccable 不會讓 Claude 知道你的品牌調性。/impeccable init 問你的問題要認真回答，CLAUDE.md 要寫。
一次改太多
發現問題的時候，一次只改一個維度。字體改完看，再改間距，再改顏色。同時改三個，你不知道是哪個造成的差異。

這套流程的核心是把「我喜歡這個」轉換成「這個由這些元素構成」。模型不缺能力。它缺的是你的參考、你的詞彙、你的禁止清單。這三樣東西建立起來之後，同樣的工具在你手上會產出跟別人完全不同的東西。
