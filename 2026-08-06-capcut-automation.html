一、這不是外掛

CapCut 沒有開放時間軸的公開 API，所以沒有任何工具能即時操作 CapCut 的介面。實際運作方式是：Claude 呼叫 MCP server，server 在你硬碟上生成一個 CapCut 草稿資料夾，你把它複製進 CapCut 的草稿目錄，打開就是排好的時間軸。

二、輸出那一步它做不了

CapCut 沒有指令列的 export 功能。算圖、輸出成品，最後還是你自己按。

三、草稿格式沒有官方文件

這些工具都是逆向工程社群做出來的。CapCut 一改版就可能整套失效。把它當成會壞的工具，不要當成生產環境的核心。

路線二砍掉錄壞的段落 · SmartCut
它的邏輯很聰明：不去分析音訊波形，改去讀 CapCut 自己生成的自動字幕。字幕代表有人在講話，字幕之間的空隙代表沒人講話，超過一秒的空隙就砍掉。更好用的是重複偵測：同一句話你錄了三次，它會判斷這是重錄，把前面兩次刪掉，留最後一次。

本機跑，不需要 API key。想加強重複偵測的準確度，可以選填 OPENAI_API_KEY 讓 GPT 幫忙判斷。

兩個常見誤解
✕ 誤解一以為草稿裡包含影片檔。草稿只是一份說明書，記錄「哪個時間點播放哪個路徑的檔案」，素材本身不在裡面。所以你不能把素材搬走、改名，或把草稿複製到另一台電腦就期待它能用。
✕ 誤解二以為可以叫 Claude 輸出成品。沒有辦法。CapCut 沒有指令列輸出的功能。要全自動輸出，得走 ffmpeg 那條路，但那就不是 CapCut 了。

不建議使用的情況
✕ 別裝你一週剪不到兩支片。安裝與排錯的時間會超過它替你省下的時間。
✕ 別裝你的內容每支結構都不一樣。這套的價值在重複，不在創意。
✕ 別裝你完全沒碰過終端機。這不是點兩下就能裝的東西，中間卡住的機率不低。
✕ 別裝你在接客戶案子，交期不能延。工具會壞，壞的時候你沒有備案。
適合使用的情況
✓ 可以裝你有固定的影片模板，每週要出好幾支。
✓ 可以裝你錄一鏡到底的口播，剪停頓佔掉你大半時間。
✓ 可以裝你已經在用 Claude Code，多裝一個 MCP 對你不是門檻。
✓ 可以裝你願意接受它偶爾壞掉，壞掉的時候手動剪也不會死。
