1-3 Skills 是什麼

一個 skill 就是一個資料夾，裡面放一份 SKILL.md。檔案開頭用 YAML frontmatter 寫 name 和 description，下面寫做事的步驟。放在哪裡決定誰吃得到：

路徑範圍
~/.claude/skills/個人用，這台電腦每個專案都吃得到
.claude/skills/專案用，跟著這個 repo 走

為什麼裝一堆 skill 不會塞爆 context：Claude Code 用的是漸進式載入，分三層。

Metadata（name + description）：開機時全部載入，每個 skill 大約 100 tokens。它只靠這幾行決定要不要用你的 skill
SKILL.md 本文：任務跟 description 對上了，才把整份讀進來
附帶檔案（scripts / references / assets）：SKILL.md 裡面叫到才載
⚠️ 所以 description 那一行是整個 skill 最重要的地方。寫得含糊，skill 永遠不會被觸發。三個寫法原則：寫「什麼時候該用」不只寫「這是什麼」／把使用者可能會講的話寫進去／用祈使句不用建議句（寫「一律使用此 skill」比「可以考慮使用」有效得多）。

# 今日計畫

## 執行步驟

1. 讀取 ~/vault/daily/ 底下今天日期的檔案（格式 YYYY-MM-DD.md）。若不存在，建立一份。
2. 讀取昨天的檔案，找出標記為未完成的項目，主動詢問使用者是否要延續。
3. 請使用者口述今天要做的事。使用者可能一次講很多件，也可能只講一件。
4. 把口述內容整理成「最多三件」的優先順位。超過三件時，主動指出哪些應該往後排，並說明理由。
5. 用以下格式寫入當日檔案的「今日三件事」段落。

## 寫入格式

## 今日三件事
- [ ] 1. 第一優先，一句話說清楚做完長什麼樣
- [ ] 2. 第二優先
- [ ] 3. 第三優先

### 延後
- 被排掉的項目，附一句為什麼

## 規則

- 每一項都要寫成「可以判斷完成與否」的敘述。寫「處理提案」不行，寫「把提案第二版寄給客戶」可以。
- 不主動幫使用者新增他沒講過的待辦。
- 寫完之後把三件事複誦一次，讓使用者確認。

# 筆記庫讀寫

Vault 根目錄：~/vault

## 目錄用途

| 資料夾 | 放什麼 |
|---|---|
| raw/ | 原始素材，剪貼、逐字稿、擷取的資料 |
| wiki/ | 整理過的知識，一個主題一份 |
| outputs/ | 產出的成品，文案、腳本、企劃 |
| daily/ | 每日紀錄，檔名 YYYY-MM-DD.md |

## 寫入規則

1. 新筆記一律放進對應的資料夾，不要放在 vault 根目錄。
2. 每份筆記開頭加 frontmatter：

3. 提到其他筆記時用 [[雙向連結]] 語法，Obsidian 會自動建立關聯。
4. 寫入前先搜尋 vault 有沒有相近主題的既有筆記。有的話，優先更新既有筆記，不要另開一份。

- 使用者問「我之前寫過什麼」時，先用關鍵字搜尋整個 vault，把找到的檔名列出來讓使用者選，不要一次讀完所有檔案。

- 找不到就直說找不到，不要用推測的內容補。

# 早晨摘要

## 執行步驟

1. 讀取 ~/vault/daily/ 昨天的檔案。
2. 找出：昨天完成了什麼、有哪些未打勾的項目、有沒有寫下待追蹤的事。
3. 讀取今天的檔案（若已存在）。
4. 產出摘要。

## 輸出格式

摘要要能直接念出來，所以：

- 用完整句子，不用條列符號
- 不超過六句
- 順序：昨天做完什麼 → 有什麼沒做完 → 今天已排了什麼 → 提醒一件最該注意的事
- 數字用口語講法。寫「三件」不寫「3 件」

## 規則

- 沒有昨日檔案時，直接說「昨天沒有紀錄」，不要編。
- 摘要結尾問一句「要現在排今天的三件事嗎」。

# 平台數據紀錄

資料檔：~/vault/wiki/metrics.md

## 執行步驟

1. 讀取 ~/vault/wiki/metrics.md，取得最近一次紀錄。
2. 向使用者取得本次數據。來源可以是：口述的數字、貼上的文字、匯出的 CSV 檔路徑。
3. 把本次數據追加成新的一列。
4. 與上次紀錄比較，算出變化量，用一句話講結論。

## 資料格式

| 日期 | 平台 | 追蹤數 | 觸及 | 互動 | 備註 |
|---|---|---|---|---|---|
| 2026-08-23 | Instagram | 12,400 | 88,000 | 3,100 | 輪播貼文 |

## 規則

- 使用者沒給的欄位留白，不要填 0，也不要推估。
- 比較時只講事實變化。不要下「表現很好」這種評價。
- 使用者問「為什麼掉了」時，回答要基於 vault 裡有紀錄的內容。沒有紀錄支撐的原因，直接說「這個 vault 裡沒有紀錄可以判斷」。

## 注意

此 skill 不會自動連線到各平台。要自動抓取，需要另外接該平台的 API 或 MCP server，那是另一個題目。這裡處理的是「把數字留下來並且看得出趨勢」。

03耳朵 · 本地語音辨識 STT本機
兩個選擇，都是 MIT 授權，模型下載後可以完全離線跑。
選項 A · whisper.cpp（不需要 Python）

適合不想碰 Python 環境的人。單一 C++ 執行檔，Apple Silicon 有 Metal 加速。

GitHub · ggml-org/whisper.cpp
編譯
git clone https://github.com/ggml-org/whisper.cpp
cd whisper.cpp
cmake -B build
cmake --build build -j --config Release
下載模型（中文建議至少 small）
./models/download-ggml-model.sh small
模型檔案大小中文表現
tiny約 75 MB只適合測試
base約 148 MB短句勉強
small約 488 MB日常口述可用
medium約 1.5 GB明顯更準
large-v3約 3.1 GB最準，也最慢
轉錄前先轉成 16kHz 單聲道 WAV
ffmpeg -i input.m4a -ar 16000 -ac 1 -c:a pcm_s16le output.wav
跑轉錄
./build/bin/whisper-cli -m models/ggml-small.bin -l zh -f output.wav -otxt
中文輸出的兩個坑

坑一，Whisper 預設輸出簡體中文。用 --prompt 給一段繁體的引導句可以改善：

繁體引導句
./build/bin/whisper-cli -m models/ggml-small.bin -l zh \
  --prompt "以下是繁體中文的逐字稿。" \
  -f output.wav -otxt
這個做法有效但不保證。要 100% 確定，最省事的方式是轉完之後跑一次簡轉繁（OpenCC 之類的工具），或者直接讓 Claude Code 幫你轉。
⚠️ 坑二，不要用 -l auto。中文語音用自動偵測很容易被判成日文或粵語，明確指定 -l zh 比較穩。
選項 B · faster-whisper（Python，速度較快）

同樣的 Whisper 模型，用 CTranslate2 重寫推論，速度和記憶體都比原版好。

GitHub · SYSTRAN/faster-whisper
安裝與使用
pip install faster-whisper
Python 範例
from faster_whisper import WhisperModel

model = WhisperModel("small", device="cpu", compute_type="int8")

segments, info = model.transcribe(
    "output.wav",
    language="zh",
    initial_prompt="以下是繁體中文的逐字稿。",
)

for segment in segments:
    print(segment.text)
有 NVIDIA 顯卡的話把 device 改成 "cuda"、compute_type 改成 "float16"，會快很多。

04嘴巴 · 本地語音合成 TTS本機
主要選擇：Kokoro-82M。82M 參數的小模型，Apache 2.0 授權，可商用。CPU 也跑得動，支援包含中文在內的多個語言，官方提供 54 個語音。
Hugging Face · Kokoro-82M 模型卡
安裝
pip install kokoro soundfile
基本用法
from kokoro import KPipeline
import soundfile as sf

# lang_code 依語言指定，中文語音的 voice 以 zf_ / zm_ 開頭
pipeline = KPipeline(lang_code='z')

text = "今天的三件事已經寫進筆記了。"

for i, (gs, ps, audio) in enumerate(pipeline(text, voice='zf_xiaobei')):
    sf.write(f'output_{i}.wav', audio, 24000)
⚠️ Kokoro 的 API 和可用語音清單會隨版本調整。上面這段是常見用法，實際參數請以模型卡頁面上的最新說明為準。第一次跑之前先去 Hugging Face 頁面看一眼 voice 清單。
關於 Piper

Piper 常被推薦，因為它極輕量，樹莓派都跑得動。但原本的 rhasspy/piper 專案在 2025 年 10 月已封存為唯讀，維護轉移到別的組織。它現在還能用，如果你已經在跑就不必換，但新開始的專案建議先看 Kokoro。

中文 TTS 的現實

英文的本地 TTS 已經很接近雲端服務的水準。中文還有差距，尤其是多音字和語氣。兩個實用的處理方式：

摘要唸出來用本地就夠。早上聽今天有什麼事，語氣自然度沒那麼重要。
要對外發布的配音，還是用雲端服務。本地 TTS 的定位是「不用付費、不用等網路、資料不外傳」，不是「取代專業配音」。

幫我做一個本機用的個人儀表板，單一 HTML 檔案，不要用框架。

視覺：深色終端機風格，等寬字體，背景近黑，重點資訊用橘色。

要顯示的內容：
1. 今天日期與時間
2. 今日三件事（從 ~/vault/daily/ 今天的檔案讀「今日三件事」段落，未打勾的顯示為待辦）
3. 昨天完成的項目數量
4. 最近七天的每日紀錄字數，做成一個簡單的長條圖
5. vault 各資料夾的檔案數量

資料來源：直接讀 ~/vault 底下的 markdown 檔案，不要用資料庫。

其他要求：
- 單頁，不要分頁，不要側邊選單
- 每 60 秒自動重新讀取一次檔案
- 讀不到檔案時顯示「無紀錄」，不要顯示錯誤堆疊
- 全部繁體中文介面

做完之後告訴我怎麼在瀏覽器打開它。

調圖表

加區塊

調配色

為什麼要自己做而不是找現成的
現成的儀表板工具要你把資料放進它的格式。這個做法反過來：資料留在你的 markdown 檔案裡，儀表板只是一個讀取器。哪天你不想用了，刪掉那個 HTML 檔就好，筆記完全沒受影響。

卡住的時候

Claude Code 說找不到我的 skill
檢查三件事：檔名是不是 SKILL.md（大小寫要對）、frontmatter 的 --- 有沒有上下各一行、description 有沒有寫進使用者實際會講的那句話。改完重開 Claude Code。
Claude Code 每次都要我確認才肯寫檔案
這是預設的安全機制。可以在 skill 的 frontmatter 用 allowed-tools 限定它能用哪些工具，或在 session 中授權一次。不建議為了方便就全部放行，尤其 vault 裡有你所有的東西。
語音辨識常常認錯專有名詞
whisper 的 --prompt / initial_prompt 可以放你常講的名詞。把品牌名、人名、工具名寫成一句話當引導，準確率會明顯改善。
中文轉出來是簡體
先用 --prompt 給繁體引導句。如果還是不穩，最省事的方式是讓 Claude Code 在寫入 vault 之前統一轉一次繁體，直接寫進 vault skill 的規則裡。
