30 個 Prompt

Prompt 直接複製

1診斷 · #01-#04 · 打開軟體之前先做完
這一段在做什麼：定義這份 dashboard 要支撐什麼決策。這四個 prompt 的產出會被後面六個階段一直引用，建議把 AI 的回覆存下來。
#01顧問式需求訪談
什麼時候用：專案第一個動作，還沒碰任何資料的時候。
#01 顧問式需求訪談
我要做一個 [主題] 的 dashboard，使用者是 [誰]。

在做任何視覺之前，先用一個資深 BI 顧問會問的 5 個問題訪談我，一次問一題，等我回答完再問下一題。

你要問出來的東西包含：
1. 這份 dashboard 支撐的是哪一個具體決策
2. 使用者看完之後會採取什麼行動
3. 哪 3 個數字最重要，排序理由是什麼
4. 使用頻率（每天／每週／每月／臨時查）
5. 哪些東西刻意不放進去，理由是什麼

訪談完之後，用 5 行總結這個專案，給我確認。
變數：[主題] 例如「電商月營收」「客服工單效率」；[誰] 例如「業務主管」「營運長」。接下來：把 5 行總結存起來，後面很多 prompt 會叫你貼上。
#02受眾與決策定位
什麼時候用：同一份 dashboard 有多個對象在看的時候。
#02 受眾與決策定位
這份 dashboard 的預期受眾是 [列出所有會看的角色]。

幫我分析：
1. 每個角色關心的問題分別是什麼（用他們自己會講的話寫）
2. 每個角色看完之後可能採取的行動
3. 這些角色之間有哪些需求是衝突的
4. 如果只能服務一個角色，應該是誰，理由是什麼
5. 其他角色的需求，建議用什麼方式處理（分頁、篩選器、另做一份、直接不做）

最後給我一個建議：這份 dashboard 的主受眾定為誰，其他人怎麼安置。
變數：[列出所有會看的角色] 例如「業務主管、財務、總經理、第一線業務」。
#03範圍收斂
什麼時候用：需求清單開始膨脹的時候。這個 prompt 的作用是砍東西。
#03 範圍收斂
以下是這個 dashboard 目前被提出的所有需求：
[貼上需求清單]

專案背景：[貼上 #01 的 5 行總結]

用一個要對交期負責的專案負責人角度，幫我分成三類：

【核心】沒有這個 dashboard 就不成立，第一版必做
【延伸】有價值但可以第二版，寫下延後的理由
【砍掉】對主決策沒有幫助，寫下砍掉的理由

每一項都要標註：
- 資料取得難度（高／中／低）
- 製作工時估計
- 對主決策的貢獻度（高／中／低）

最後告訴我：第一版的範圍應該包含哪幾項，總共幾個視覺元件。
#04一頁專案規格書
什麼時候用：階段 1 收尾，開始動手之前的最後一步。
#04 一頁專案規格書
根據以下資訊，幫我寫一份一頁的 dashboard 規格書：

專案總結：[貼上 #01 的 5 行總結]
主受眾：[貼上 #02 的結論]
第一版範圍：[貼上 #03 的核心清單]

規格書要包含這些欄位：
1. 專案名稱與一句話目的
2. 主受眾與使用情境（在哪裡看、什麼時候看、看多久）
3. 支撐的決策
4. 頂欄 KPI（3 到 5 個，只寫名稱與定義，計算公式之後再處理）
5. 頁面架構（幾頁、每頁負責回答什麼問題）
6. 資料來源與更新頻率
7. 明確排除項目（寫清楚不做什麼）
8. 驗收標準（怎樣算做完）

用表格排版，我要能直接貼給需求方確認。
這份規格書是整個專案的參考點。後面每一個階段的 prompt 都可以貼上這份文件當背景。
2清理 · #05-#09 · 畫第一張圖之前
這一段在做什麼：把底層資料弄乾淨。這個階段的 prompt 建議用有程式碼執行能力的 AI 工具跑（Claude、ChatGPT 的資料分析模式）。
#05資料欄位盤點
什麼時候用：拿到原始檔案，還沒開始清的時候。
#05 資料欄位盤點
這是我的原始資料 [上傳檔案／貼上前 30 列]。

幫我做一份欄位盤點表，每個欄位列出：
1. 欄位名稱
2. 推測的資料型別（文字／數值／日期／布林）
3. 實際內容範例（3 筆）
4. 空值比例
5. 唯一值數量
6. 我推測這個欄位的用途（維度／量值／識別碼／可能沒用）

盤點完之後，告訴我：
- 哪些欄位看起來是重複的或衍生的
- 哪些欄位命名不清楚，建議改成什麼
- 哪些欄位可能可以直接刪掉，理由是什麼
#06資料 X 光健檢
什麼時候用：盤點完欄位之後，正式清理的核心 prompt。
#06 資料 X 光健檢
用程式碼分析這份資料，給我一份 X 光檢查，逐項檢查：

1. 重複值：完全重複的列、以及應該唯一但重複的鍵值
2. 不可能出現的數值：負數金額、超出合理範圍的數字、未來日期
3. 空欄位：哪些欄位有空值、比例多少、空值集中在哪些列
4. 寫法不一致：同一個意思但寫法不同的文字（大小寫、全半形、空白、簡稱）
5. 日期格式混亂：同欄位出現多種日期格式
6. 加總對不起來：明細加總與彙總欄位的差額
7. 孤兒資料：明細表有但主檔沒有的鍵值

每一個問題都要寫清楚三件事：
- 出現在哪（欄位、大概幾列、舉 2 個實例）
- 會怎麼影響 dashboard（具體說會讓哪個數字錯）
- 怎麼修（給我修正的程式碼）

最後給我一份清乾淨、結構化的單一表格，並附上一份修改紀錄。
#07星型模型建模
什麼時候用：資料清乾淨之後，準備進 Power BI 之前。
#07 星型模型建模
這是我清理過的資料：[上傳／貼上欄位清單]。

幫我設計成星型模型（Star Schema）：
1. 哪些欄位屬於事實表（Fact），哪些屬於維度表（Dimension）
2. 事實表的粒度是什麼（一列代表什麼事件）
3. 每個維度表需要哪些欄位、主鍵是什麼
4. 事實表與維度表之間的關聯方式與基數（一對多／多對多）
5. 有沒有需要處理的多對多關係，建議怎麼處理

輸出格式：
- 一張模型結構圖（用文字或 Mermaid 語法表示）
- 每張表的欄位清單
- 建立這些表的程式碼

另外告訴我：這個模型有哪些地方之後可能會出問題。
#08類別對照與命名統一
什麼時候用：資料裡同一個東西有很多種寫法的時候。
#08 類別對照與命名統一
這是我的 [欄位名稱] 欄位的所有唯一值：
[貼上唯一值清單]

幫我：
1. 找出實際上是同一個東西、但寫法不同的值，分組列出
2. 每一組建議一個標準寫法，並說明選擇理由
3. 建立一份對照表（原始值 → 標準值）
4. 標出你不確定該怎麼歸類的值，讓我自己判斷
5. 給我套用這份對照表的程式碼

對照表請用可以直接匯入的格式輸出（兩欄式表格）。
變數：[欄位名稱] 常見的是「客戶名稱」「產品類別」「地區」「業務員」。
#09日期表建立
什麼時候用：只要 dashboard 有任何時間維度的分析就需要。
#09 日期表建立
幫我建立一張標準日期表，用於 Power BI 的時間智慧函數。

需求：
- 期間範圍：[起始日] 到 [結束日]
- 會計年度起始月：[月份，一般公司填 1]
- 語系：繁體中文，台灣用法

日期表需要包含這些欄位：
日期、年、季、月、月份名稱、週次、星期幾、
年月（排序用數字格式）、年季、
是否為工作日、是否為月底、是否為季底、
會計年度、會計季、會計月、
相對月份索引（本月為 0，上月為 -1，用於相對期間篩選）

請給我：
1. 建立這張表的 DAX 程式碼
2. 建立這張表的 Power Query M 程式碼
3. 建好之後要在 Power BI 做哪些設定（標記為日期表、建立關聯、排序欄位設定）
4. 常見的三個設定錯誤與檢查方式
3數字 · #10-#14 · 讓 dashboard 會思考的量值
這一段在做什麼：設計 KPI 與量值計算邏輯。這個階段的 DAX 語法是 Power BI 專屬，其他工具可以請 AI 轉換成對應語言。
#10指標定義字典
什麼時候用：開始寫公式之前。這一步能擋掉大部分「兩個部門算出來的數字不一樣」的問題。
#10 指標定義字典
這份 dashboard 會用到以下指標：
[列出指標名稱，例如：營收、毛利率、客單價、回購率]

專案背景：[貼上 #04 的規格書]

幫我針對每一個指標建立定義卡，包含：
1. 指標名稱（中英文）
2. 一句話定義
3. 計算方式（文字描述，不要程式碼）
4. 分子與分母各自的來源欄位
5. 計入範圍與排除條件（例如：退貨算不算、內部訂單算不算、測試資料怎麼排除）
6. 常見的三種不同算法，以及各自適用的情境
7. 這個指標容易被誤讀的地方

最後，把所有定義整理成一張表，我要放進文件裡給團隊對齊。
#11KPI 提案與 DAX 量值
什麼時候用：定義字典做完之後，這個階段的核心 prompt。
#11 KPI 提案與 DAX 量值
根據這份 dashboard 的目標：
[貼上 #01 的 5 行總結，或 #04 的規格書]

指標定義：[貼上 #10 的定義表]

第一步，提出最上排的 4 個 KPI，每一個要寫：
- 名稱
- 計算公式（文字描述）
- 為什麼這一個值得佔據最顯眼的位置
- 如果拿掉會失去什麼

第二步，給我每一個 KPI 的 DAX 量值程式碼，要求：
- 逐行加上中文註解
- 使用變數（VAR）讓邏輯清楚
- 除法一律使用 DIVIDE 避免除以零
- 標出這個量值在什麼情況下會算錯或誤導人（例如篩選情境、空值處理、粒度不符）

第三步，告訴我這 4 個 KPI 之間有沒有互相矛盾的可能，以及怎麼在版面上處理。
#12年度累計與期間比較
什麼時候用：需要「跟上個月比」「跟去年同期比」的時候。
#12 年度累計與期間比較
我的日期表叫做 [日期表名稱]，日期欄位叫做 [欄位名稱]。
我要做期間比較的基礎量值是：[貼上基礎量值的 DAX，例如 總營收]

幫我寫出以下量值的 DAX 程式碼，每一個都要有中文註解：
1. 年度累計 YTD
2. 季度累計 QTD
3. 月度累計 MTD
4. 上一期間同期（PP）
5. 去年同期（PY）
6. 與上期比較的成長率（%）
7. 與去年同期比較的成長率（%）
8. 滾動 12 個月合計

每一個量值後面附上：
- 這個量值在什麼篩選情境下會失效
- 會計年度不是 1 月起始的話要改哪裡
- 資料還沒填滿當月時，數字會怎麼失真，怎麼處理
#13動態排行 TOP N
什麼時候用：需要「前十大客戶」「銷售最好的五個產品」這種視覺的時候。
#13 動態排行 TOP N
我要做一個動態排行視覺，需求如下：
- 排行對象：[例如 客戶／產品／業務員]
- 排行依據：[例如 總營收]
- 顯示筆數：可由使用者調整（3、5、10、20）

幫我：
1. 建立參數表的方法與 DAX 程式碼
2. 排行量值的 DAX（要能跟著篩選器動態變化）
3. 把未進榜的項目合併成「其他」的量值寫法
4. 處理同分並列的邏輯
5. 讓排行在切換篩選器（時間、地區）時正確重算的注意事項

另外告訴我：這個做法在資料量大的時候會不會有效能問題，怎麼優化。
#14目標 vs 實際
什麼時候用：有預算、有目標、需要看達成率的 dashboard。
#14 目標 vs 實際
我有一張目標表：[描述欄位，例如：年、月、部門、目標金額]
實際數字來自：[描述來源，例如 銷售明細表]
粒度差異：目標是 [月／部門] 層級，實際是 [每筆交易] 層級。

幫我：
1. 設計目標表與事實表的關聯方式（處理粒度不一致的問題）
2. 寫出以下量值的 DAX，附中文註解：
   - 目標金額
   - 實際金額
   - 達成率（%）
   - 差額（實際 - 目標）
   - 累計達成率
   - 按進度換算的應達成金額（月中看的時候用）
3. 設計達成率的顏色門檻邏輯（DAX 條件式格式）
4. 標出：使用者在鑽取到目標表沒有的層級時會發生什麼，怎麼處理

最後說明：這個模型在新增一個沒有設目標的部門時會怎樣。
4視覺 · #15-#19 · 把散圖變成有層級的版面
這一段在做什麼：把一堆散圖變成顧問等級的版面。#17 需要你上傳截圖，截完整畫面，不要只截局部。
#15專業配色系統
什麼時候用：開始排版之前，先把顏色定下來。
#15 專業配色系統
我要為一份 [主題] 的 dashboard 設計配色系統。

限制條件：
- 品牌主色：[色碼，沒有就填「無」]
- 使用場景：[螢幕／投影／列印]
- 主要受眾：[例如 高階主管]

請給我一套配色系統，包含：
1. 背景色、卡片底色、分隔線色（各一個色碼）
2. 主要文字色、次要文字色、標籤文字色
3. 資料色階：5 個依序的類別色（要在色盲友善的前提下可分辨）
4. 語意色：正向、負向、中性、警示（各一個色碼）
5. 強調色：只用在最重要的那一個數字

每個顏色都要附：
- 色碼
- 使用時機
- 禁止用在哪裡

另外檢查：主要文字色與背景色的對比度是否達到 WCAG AA 標準，附上實際對比值。

最後告訴我：這套配色最容易被誤用的地方是什麼。
#16Z 型版面配置
什麼時候用：知道要放哪些視覺元件，但不知道怎麼排的時候。
#16 Z 型版面配置

  • 把階段 1 的產出存好。#01 到 #04 的結果會在後面二十幾個 prompt 裡被反覆引用。建議在 Notion 開一個專案頁面，把這四份產出貼在最上面。
  • 方括號一定要填完再送出。[主題]、[誰]、[貼上 #01 的總結] 這些留著不填，AI 會自己編一個假的情境，後面全部會歪掉。
  • 同一個專案用同一個對話串。跨對話串的話 AI 記不得前面的決策，你每次都要重貼背景。
  • #17、#23、#25 需要上傳截圖。截圖請截完整畫面，不要只截局部，AI 沒辦法判斷版面比例。
  • 這份流程不是只能用在 Power BI。除了階段 3 的 DAX 語法之外，其他 27 個 prompt 在 Tableau、Looker Studio、Google Sheets 上都能用。
⚠️ DAX 產出的程式碼要自己驗過。AI 寫的 DAX 語法通常正確，但商業邏輯是否符合你們公司的算法，要自己核對一次。特別是 #12 的期間比較與 #14 的達成率，這兩個最容易算出「語法沒錯但意思不對」的結果。
